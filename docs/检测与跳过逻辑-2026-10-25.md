# 视频像素化检查：检测、历史与复用规则

> 对应3.24.0。代码入口：censor/service.py、scan_plan.py、review_route.py、store.py、mosaic_cv.py。旧说明中“名称可免检”“没抽到就低风险”“自动结论即完成”不再作为操作依据。

## 证据和状态

| 来源 | 作用及边界 |
|---|---|
| 人工确认MANUAL | 仅同一文件版本、权威标签中有效的有码/无码确认优先；UNKNOWN不算确认。撤回不能被旧扫描恢复。 |
| 名称、系列、NFO和服务器标签 | 提供线索和调度提示；不能证明画面不存在像素化，不按前缀免检。仅元数据不能自动定性。 |
| 视觉抽样 | 提供局部结构候选；不足以证明全片不存在像素化，未知时长和覆盖不足不能归低风险。 |

“结论”（有码/无码/未定）、“执行状态”（完成/失败等）、“处理桶”分别记录。保留有效人工确认的失败重检仍是已确认，失败原因仍可查看。自动疑似结论仍可能待复核。

| 处理桶 | 实际含义 |
|---|---|
| 排队中 | 尚无分析结果。 |
| 未完成 | 无有效人工确认，且检查失败、取消或只完成一部分。 |
| 已确认 | 有当前文件版本的有效人工明确结论。 |
| 低风险 | 未定结论，视觉证据满足抽样覆盖和独立画面等门槛且不要求复核；不是全片无像素化认证。 |
| 已延后 | 符合名称调度提示，尚未完成所需画面核验；不是确认。 |
| 待复核 | 其余需要人工处理的结果，包括自动疑似像素化。 |

## 扫描和缓存

直接文件、文件夹发现和媒体库路径都先尝试有效缓存，再判断是否延期；显式force/recheck_manual不被名称延期拦截。缓存命中也会完成持久待办和来源，避免恢复后重复扫描。媒体库扫描只处理当前机器能访问的本地路径。

普通自动缓存比较路径、文件身份、参数/检测器版本及外部输入签名；旧视觉检测器5的自动缓存可能在版本6下失效。大小、时间、文件身份或输入变化是否触发重算，须结合人工确认分支判断，不能简单宣称“任何NFO变化都重扫”。当前文件版本的有效人工确认按专门规则保留；强制分析也不等于撤回人工确认，重新核验人工记录使用对应显式操作。

普通重新导入会复用有效结果；缺少有效缓存的文件才进入分析或延后流程。首次导入也可能因已有人工确认、已有历史或名称延期而不启动视觉抽样，不能假设所有文件都会立即抽帧。

缓存回填、历史和扫描结果通过有界呈现队列分批显示，交还GUI事件循环；这只是显示批次，不是历史加载条数上限，也不需要重复点击“加载更多”。

## 历史保存与兼容

资料库由固定资料库登记决定，而非每版EXE所在目录决定。升级保留已有登记和数据库，不要求每次手工导出再导入；当前本机登记指向v2数据目录仍可正常使用。不要仅因换了程序目录就删除旧资料库。

启动/手动历史加载从SQLite读取已有记录，不抽帧、不联网。普通历史和复核队列在同一读取快照中关联对应文件身份的权威人工标签和撤回记录，纠正旧错误MANUAL投影；不猜跨版本身份，不批量改写旧分析。保留原候选、时间、签名和视觉证据。底层stats原始聚合仍描述保存时分析分布，界面工作流按投影后结果分类。

显式重扫才会访问媒体。文件被替换时旧人工确认不得直接套到新版本；原有人工历史保留，供追溯。

## 抽样和证据输出

首轮、全量和补检共用低风险条件。除分数、成功采样数和独立画面数外，还检查已知有效时长、首段与尾段覆盖；时间覆盖不足需复核。视频轨比容器时长短、重复帧或EOF均可能降低可用证据，不能把计划采样数当成实际成功数。

所有图片格式先验证像素尺寸/通道，再临时编码并原子替换。EOF、超时、取消、编码失败保留已有图片但返回失败，不用旧图片冒充本次成功；PNG路径不额外启动编码子进程。

本轮没有真实大库吞吐或内容准确率基准，不给出跨机器速度承诺。详细修复、验证及局限见[检修记录](通用检测检修-2026-10-25.md)。
