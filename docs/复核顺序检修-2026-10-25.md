# 3.24.1：表格选择、标记按钮与下一条专项检修

用户本次明确选择：自动下一条处理当前筛选可见且尚未人工确认的视频。所有验证使用隔离资料库、普通合成文件和离屏Qt，不读写用户真实媒体、NFO或Jellyfin。

## 用户可依赖的顺序

1. 以表格当前排序为准，单条保存前记录行序；保存可能改变结论/处理排序、隐藏当前行，但跳转位置不因此丢失。
2. 从刚保存视频向下找当前筛选可见且未确认的下一条，包括主动打开的低风险/已延后项；跳过已确认。到末尾查前面剩余项，没有其他候选就清空选择并提示，不会重复标记最后一条。
3. 没有选择时点击标记只提示，不修改数据。手动下一条可按保留的表格焦点向后找；首次无焦点则定位第一候选。
4. 鼠标与快捷键统一入口。单选保存当前项，多选弹出原有批量人工确认清单，取消清单不保存。
5. 批量全成功后，等待保存结果全部渲染，再从原选中范围最下面一行之后跳一次。失败、取消、停止、关闭自动下一条、配置上下文变化时不自动跳；已选择其他视频时保留新的选择。停止代次防止已排队的旧完成事件触发跳转。
6. 关闭自动下一条且当前视频仍符合筛选时，继续选中同一视频；若保存后不再符合筛选，清空选择，不越过筛选强行留行。

“包括低风险/已延后”只改变导航可选范围，不改变其分类，不自动确认、不写标签，也不纳入原待办数量。当前只看已确认的筛选里没有未确认候选时不会自动移动；仍可直接点选需要改判的视频。

## 发现和修复

| 行为 | 根因 | 改动 |
|---|---|---|
| 清选后按钮偷偷标记旧焦点；最后一项可能反复改判 | _resolve_current把未选中的currentRow或第一可见行当目标 | 只能使用显式可见选择；保留按钮可点与明确提示。 |
| 多选鼠标只标一项，快捷键却批量 | 按钮直接_label，快捷键另做分发 | 共同_confirm_selected入口，原批量确认清单保留。 |
| 清选后手动下一条从头开始 | _current清空后直接传空串，没有使用保留表格焦点 | _next_review明确解析导航锚点；保存目标与导航锚点分开。 |
| 低风险/延后列表确认一条后停止 | needs_review把用户主动打开的非待办也排除 | 当前可见且ReviewBucket非CONFIRMED即可继续；不改变分类函数。 |
| 批量成功后不自动跳转 | 批量链路无导航，结果异步呈现尚未结束 | 保存前记录顺序/选中范围，报告和呈现均完成后跳一次。 |
| 已停止仍被旧批量完成事件带走 | 只看报告cancelled，保存后报告可能已经排队 | 关联页面_task_epoch，停止使旧导航失效。 |

确认前顺序快照是3.24.0已经修复的部分，本轮未推翻。普通表头排序与筛选的身份一致性、名称/结论/处理的升降序连续四次标记、自动下一条关闭等场景最初就通过，不据此声称发现新bug。
