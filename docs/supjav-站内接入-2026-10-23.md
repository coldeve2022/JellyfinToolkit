# Supjav 站内检索接入

用户明确要求实际加入 Supjav 站内渠道，只读取文字元数据，不下载视频。

实测：普通 HTTP 的搜索和 `/wp-json/` 均返回 403；用户确认日常浏览器可打开。浏览器连接工具未能附着到新搜索标签，因此没有把 Chrome 页面读取当作成功证据。

实现契约：

1. 默认站内优先；站内搜索取得同域文章链接，再读取详情的主标题、分类与完整番号。提供仅站内/仅索引兼容模式。
2. 站内被拦时，索引只补充软线索；尽量读取目标详情核验。失败、解析失败、截断/分页缺口不成为完整否定。
3. 在设置中提供独立 Supjav 浏览器会话。正常浏览器执行站点脚本，需人机验证时由用户完成；检索继续在同一浏览器上下文读取 HTML，避免导出 Cookie 后更换客户端。
4. 浏览器只允许 Supjav 元数据地址与 Cloudflare 挑战资源，拦截图片、视频、下载和新窗口；会话数据留在应用数据目录，不写入报告或源码。
5. 所有页面请求仍经过共同预算、同站限速、取消与超时；CLI 未启用浏览器会话时可使用既有 HTTP/FlareSolverr 传输。
6. 先写离线 HTML、站内优先/降级、串号、否定、取消、预算、浏览器请求交接测试，再运行全量。在线成功必须另外记录，不以离线通过替代。

本次是既有检索流程的专项扩展，按用户已明确授权的站内接入连续实施；不重新要求同范围权限批准。

## 最终结果（2026-10-23 收尾验收）

### 落地状态

| 契约 | 状态 | 落点 |
| --- | --- | --- |
| 站内搜索 → 同域文章 → 详情核验（主标题/分类/完整番号） | 已实现 | `censor/releases/supjav.py`（`_direct` / `_detail`）、`supjav_pages.py` |
| 三种方式：`auto` 站内优先 / `direct` 只站内 / `index` 只索引 | 已实现 | `release_supjav_mode`，设置页下拉可选 |
| 站内被拦时索引只补充软线索，目标详情尽量回站内核验 | 已实现 | `search()` 的 `auto` 分支：索引条目逐条 `_detail()` |
| 独立浏览器会话（人工过验证、复用同一上下文读 HTML） | 已实现 | `ui/supjav_browser.py`（`SupjavBrowserSession`） |
| 只放行 Supjav 元数据地址 + 挑战资源，拦截图片/媒体/下载/新窗口 | 已实现 | `Guard` 拦截器 + `acceptNavigationRequest` |
| 请求仍走共同预算、同站限速、取消、超时 | 已实现 | `transport.register_site_reader` 的预算包装 |
| 离线回归测试先于全量 | 已实现 | `tests/test_supjav_direct.py`、`tests/test_supjav_browser.py` |

### 本轮收尾补的三处

1. **配置枚举校验**：`release_supjav_mode` 纳入 `_coerce_config` 的白名单，手改成
   `only-index` / `AUTO` / 空串之类的值会**回落默认 `auto`**，不再进入不可预期分支。
2. **浏览器会话边界**：
   - 会话已销毁时 `read()` **立刻**报"已关闭"，不再先白等锁满 45 秒；
   - 取消时页面已随窗口销毁，`triggerAction` 抛的 `RuntimeError` 被吞掉（取消本身已生效）；
   - `dispose()` 现在连 `_view` 一起摘掉并把 `_page` / `_profile` 置空，重连不会叠控件。
3. **旧说明清理**：`docs/无码版本检索.md`、`config.py`、`config.example.json`、
   检查页帮助文案里"Supjav 只能查索引 / 不需要浏览器"的表述全部改成"站内优先、索引补充"。

### 验证证据

- 离线：`tests/test_supjav_direct.py`（串号、挑战页、解析失败、分类污染、取消、软线索、
  有效空结果）+ `tests/test_supjav_browser.py`（预算、地址白名单、媒体/外链拦截、
  旧页面回调不能完成新导航、后台线程→GUI 交接、打包不得排除浏览器后端、销毁边界）。
- 在线：普通 HTTP 搜索与 `/wp-json/` 均 403；浏览器会话建立后**成功取到过一次站内搜索与详情页**。
  这是一次性证据，不代表每次都能过验证 —— 遇挑战需在会话窗口手动完成。

### 已知限制（不要当成能力保证）

- 站内是否可用取决于**当时的验证状态**；没过验证时如实报"站内未完成"，索引结果仅为软线索。
- 浏览器会话需要 `QtWebEngine`（PySide6 完整包自带；`PySide6-Essentials` 没有），
  缺失时设置页会弹提示而不是崩溃。
- 本次没有做"多次在线成功率"统计，只在单次会话里验证链路通。
