# Supjav 站内检索接入

用户明确要求实际加入 Supjav 站内渠道，只读取文字元数据，不下载视频。

实测：普通 HTTP 的搜索和 `/wp-json/` 均返回 403；用户确认日常浏览器可打开。浏览器连接工具未能附着到新搜索标签，因此没有把 Chrome 页面读取当作成功证据。

实现契约：

1. 默认站内优先；站内搜索取得同域文章链接，再读取详情的主标题、分类与完整番号。提供仅站内/仅索引兼容模式。
2. 站内被拦时，索引只补充软线索；尽量读取目标详情核验。失败、解析失败、截断/分页缺口不成为完整否定。
3. 在设置中提供独立 Supjav 浏览器会话。正常浏览器执行站点脚本，需人机验证时由用户完成；检索继续在同一浏览器上下文读取 HTML，避免导出 Cookie 后更换客户端。
4. 浏览器只允许 Supjav 元数据地址与 Cloudflare 挑战资源，拦截图片、视频、下载和新窗口；会话数据留在应用数据目录，不写入报告或源码。
5. 所有页面请求仍经过共同预算、同站限速、取消与超时；CLI 未启用浏览器会话时可使用既有 HTTP/FlareSolverr 传输。
6. 先写离线 HTML、站内优先/降级、串号、否定、取消、预算、浏览器请求交接测试，再运行全量。在线成功必须另外记录，不以离线通过替代。

本次是既有检索流程的专项扩展，按用户已明确授权的站内接入连续实施；不重新要求同范围权限批准。

## 最终结果（2026-10-23 收尾验收）

### 落地状态

| 契约 | 状态 | 落点 |
| --- | --- | --- |
| 站内搜索 → 同域文章 → 详情核验（主标题/分类/完整番号） | 已实现 | `censor/releases/supjav.py`（`_direct` / `_detail`）、`supjav_pages.py` |
| 三种方式：`auto` 站内优先 / `direct` 只站内 / `index` 只索引 | 已实现 | `release_supjav_mode`，设置页下拉可选 |
| 站内被拦时索引只补充软线索，目标详情尽量回站内核验 | 已实现 | `search()` 的 `auto` 分支：索引条目逐条 `_detail()` |
| 独立浏览器会话（人工过验证、复用同一上下文读 HTML） | 已实现 | `ui/supjav_browser.py`（`SupjavBrowserSession`） |
| 只放行 Supjav 元数据地址 + 挑战资源，拦截图片/媒体/下载/新窗口 | 已实现 | `Guard` 拦截器 + `acceptNavigationRequest` |
| 请求仍走共同预算、同站限速、取消、超时 | 已实现 | `transport.register_site_reader` 的预算包装 |
| 离线回归测试先于全量 | 已实现 | `tests/test_supjav_direct.py`、`tests/test_supjav_browser.py` |

### 本轮收尾补的三处

1. **配置枚举校验**：`release_supjav_mode` 纳入 `_coerce_config` 的白名单，手改成
   `only-index` / `AUTO` / 空串之类的值会**回落默认 `auto`**，不再进入不可预期分支。
2. **浏览器会话边界**：
   - 会话已销毁时 `read()` **立刻**报"已关闭"，不再先白等锁满 45 秒；
   - 取消时页面已随窗口销毁，`triggerAction` 抛的 `RuntimeError` 被吞掉（取消本身已生效）；
   - `dispose()` 现在连 `_view` 一起摘掉并把 `_page` / `_profile` 置空，重连不会叠控件。
3. **旧说明清理**：`docs/无码版本检索.md`、`config.py`、`config.example.json`、
   检查页帮助文案里"Supjav 只能查索引 / 不需要浏览器"的表述全部改成"站内优先、索引补充"。

### 验证证据

- 离线：`tests/test_supjav_direct.py`（串号、挑战页、解析失败、分类污染、取消、软线索、
  有效空结果）+ `tests/test_supjav_browser.py`（预算、地址白名单、媒体/外链拦截、
  旧页面回调不能完成新导航、后台线程→GUI 交接、打包不得排除浏览器后端、销毁边界）。
- 在线：普通 HTTP 搜索与 `/wp-json/` 均 403；浏览器会话建立后**成功取到过一次站内搜索与详情页**。
  这是一次性证据，不代表每次都能过验证 —— 遇挑战需在会话窗口手动完成。

### 已知限制（不要当成能力保证）

- 站内是否可用取决于**当时的验证状态**；没过验证时如实报"站内未完成"，索引结果仅为软线索。
- 浏览器会话需要 `QtWebEngine`（PySide6 完整包自带；`PySide6-Essentials` 没有），
  缺失时设置页会弹提示而不是崩溃。
- 本次没有做"多次在线成功率"统计，只在单次会话里验证链路通。

## 2026-10-24 修复：站内仍然抓不到（四个叠加的根因）

用户反馈：**当前版本 Supjav 抓不到任何信息**，而同一部片（实测 YMDD-365）
在浏览器里能搜到 `[Reducing Mosaic]` 版本。

### 实测结论：解析没问题，坏在"拿不到页面"

把真实页面喂给现有解析器，一切正常：

```
search_links(搜索页, "YMDD-365")   -> 2 条
  https://supjav.com/256514.html   [Reducing Mosaic]YMDD-365 ...
  https://supjav.com/254427.html   YMDD-365 ...
detail_metadata(详情页, "YMDD-365") -> 标题 + 分类 [('Reducing Mosaic', '/category/reducing-mosaic')]
```

站点 URL 形态（`/<数字>.html`）、搜索 URL（`/?s=番号`）、主标题、分类全都没变。
所以问题全在链路的前半段，而且是**四个各自独立、单独都会导致空结果**的缺陷叠加：

| # | 根因 | 表现 | 修法 |
| --- | --- | --- | --- |
| 1 | `detect_proxy` 对显式配置不补 `http://` | 填 `127.0.0.1:7897`（最自然的写法）时 urllib 静默直连 → 连接超时 | `normalize_proxy()` 统一收敛；`http=...;https=...` 也能解析 |
| 2 | 只认"系统代理" | Clash 常只开端口、不开系统代理 → 判定无代理 → 直连 | 新增 `probe_local_proxy()`：探测本机常见端口（连通即用），带 30 分钟缓存 |
| 3 | 站内必须手动连接浏览器会话 | 忘了点设置页那个按钮，Supjav 源就永远拿到 403 | 检索前 `_ensure_supjav_channel()` 自动准备；窗口不抢焦点 |
| 4 | 页面完成判定严格比较 URL | Cloudflare 追加 `__cf_chl_rt_tk` 后 URL 不等 → 永远等不到"完成" → 45 秒超时 | `_same_target()` 忽略挑战参数与参数顺序 |

另外三个让问题更难查的点：

- **`prepare_supjav_session()` 不显示窗口**：Chromium 对不可见窗口节流定时器/rAF，
  Cloudflare 的挑战脚本跑不完 → 页面永远空白。现在 `_begin()`（GUI 线程）里确保
  `show()`，但用 `WA_ShowWithoutActivating` 不抢焦点。
- **`read()` 在后台线程里碰 GUI 会直接崩**（0xC0000005）：显示窗口的动作移到
  GUI 线程的 `_begin()`。
- **命名 profile + 自定义 storage 路径**：实测会导致 `loadFinished=False`、
  URL 始终为空（Chromium 存储初始化失败）。改用默认 profile（LOCALAPPDATA，ASCII 路径）。

### 修复后的实测

```
代理自动探测：http://127.0.0.1:7897      （无环境变量、无系统代理）
首次检索 YMDD-365：14.0s
  来源状态：{"javdb": "命中 1 条", "javbus": "命中 1 条", "supjav": "命中 2 条"}
  [supjav] [Reducing Mosaic]YMDD-365 ...  uncensored=True conf=0.6
           reason=站点标题含减码/薄码标记（reducing mosaic），未必全无码
           url=https://supjav.com/256514.html
第二次检索：6.3s（命中页面缓存）
```

### 新增的落点

- `censor/releases/transport.py`：`normalize_proxy` / `probe_local_proxy` /
  `LOCAL_PROXY_PORTS` / `RELEASE_PROXY_PROBE` 开关；`_fallback_routes` 把探测到的端口
  也排进候选（环境变量里的代理未必能转发所有站点，实测有 502）。
- `main.py`：`_inject_webengine_proxy()` 在 QApplication 之前注入
  `--proxy-server`（Chromium 只认进程级参数），并支持
  `JELLYFIN_TOOLKIT_WEBENGINE_NO_SANDBOX=1` 兼容模式。
- `ui/supjav_browser.py`：页面缓存（`data/supjav-browser/pages`，TTL 跟随
  `release_cache_days`）、`_ensure_visible`、`_same_target`、失败时的可执行提示。
- `ui/pages/censor_replace.py`：`_ensure_supjav_channel()`。
- `tests/test_supjav_reachability.py`（18 项）+ `tests/fixtures/supjav_*_real.html`
  （2026-10-24 真实页面）。

### 仍然要说清楚的限制

- 站内是否可用仍取决于**当时的 Cloudflare 验证状态**；需要人工点验证时窗口会在前台。
- 沙箱受限的环境（受限账户、部分安全软件）可能出现"浏览器内核没启动"，
  用 `JELLYFIN_TOOLKIT_WEBENGINE_NO_SANDBOX=1` 重启可解；这只影响 Supjav 只读会话。
- `[Reducing Mosaic]` 仍按"疑似 0.60"记，不会当成"确有"——它只是减码。
