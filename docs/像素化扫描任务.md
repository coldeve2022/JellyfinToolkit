# 扫描范围、排队和恢复

当前采用通用像素化检测、文件级任务恢复和分层复核，检测机制见《像素化检测》。

## 如何使用

1. 添加视频或目录。目录枚举、文件校验、NFO 读取和排序均在扫描线程执行，可以点击“停止”。
2. 先检查文件名：明确无码/破解名称优先延后，即使原始NFO仍标有码。其余优先扫描 NFO 存在像素化线索或标签冲突的文件，其次是无相关标签。只有无码/破解等相关线索的文件保存为“延后待选”，默认不检查；普通任务全部结束也不会自动检查它们。
3. 停止或关闭软件后，重新进入检测页，点击“更多 → 继续未完成任务”。发现阶段的来源目录也会保存，目录扫描中断后可以重做发现。已完成且文件、参数、算法与输入没有变化的视频复用缓存，跳过耗时画面分析。
4. “更多 → 重试失败项”将已失败的视频重新排队。断开的目录保留为未完成扫描来源，恢复连接后点“继续未完成”。
5. 点击“更多 → 历史与重新分析 → 加载历史记录”，再用筛选框选择“检出像素化”或“只看待复核”；“加载更多历史”追加下一批。清空列表只清当前视图，不清结果和任务队列。
6. 点击“更多 → 选择延后视频”，勾选要检查的项目，再点“检查勾选项目”。列表默认全部不勾选，未选项目始终保留，重启后仍可查看。手动选择的任务中断后可以继续，成功后清除本次选择授权。

标签统一做 Unicode NFKC、全角/半角、英文大小写及相关繁体字处理，支持中文词内分隔符和常见英文形式，例如 `無碼`、`無修正`、`無碼－破解`、`ＵＮＣＥＮＳＯＲＥＤ`、`Un-Censored`、`DECENSORED`、`去馬賽克` 等。`未破解`、`非流出`、`not leaked` 等否定标签不触发默认延后；同一标签或多条标签中的冲突也保留在普通队列。标签只是决定是否排队的线索，不会将延后项目标成“已检查”或“确认未见”。

队列状态保存在现有数据目录的 `censor.db` 中，使用独立表，历史结果使用原来的带签名缓存。当前提供每个路径最近一次成功结果的查询，并非每次扫描运行的完整时间线。历史查询不会自动重新读取远端 NFO；记录可能对应旧文件，重新添加时会校验文件身份。

恢复粒度为视频文件。中断的视频重新分析，已完成视频复用有效缓存。关闭程序不会暗中继续扫描，也没有添加计划任务或开机自启。

## 正片过滤

继续共用工具箱的辅助文件判定，增强带技术后缀的 trailer/sample/teaser/promo/preview、带编号样片及中文预告/花絮前缀、方括号明确标记。辅助目录、临时产物和合并备份目录仍按原规则排除。保留《Trailer Park Boys》《Sample Movie》这类正常标题，避免按任意子串粗暴排除。

命名过滤不是内容识别，无法识别所有不按约定命名的辅助视频；可使用已有的排除路径关键词补充自己的目录规则。

## 实施选择

按用户更新后的偏好，无码相关标签默认延后、仅手动选中后检查；采用文件级恢复、最近成功结果历史与有界并发，未合并或发布已有开发分支。错误不记作成功，取消的视频留在待处理队列。没有新增产品运行依赖。
