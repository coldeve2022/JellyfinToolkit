# 流程与可用性审计（2026-10-24）

触发：用户提出三个具体问题 + 要求"整体梳理一遍"。本文只写**有实证**的结论，
不列"看起来可疑"的猜测。

---

## 一、本轮已修复

### 1. FC2 番号搜索词（用户报告）

**现象**：Supjav 搜 `FC2-PPV-1631136` → `Search Result For: FC2-PPV-1631136(0)`，0 条。

**根因**：搜索词与复核词用的是同一个值（规范化番号）。FC2 在各站写法不统一
（`FC2-PPV-x` / `FC2PPV x` / 纯数字），把整串丢给站内搜索经常 0 命中。

**修复**：拆成两个概念，集中在 `censor/releases/base.py`：

| 概念 | 函数 | 规则 |
| --- | --- | --- |
| 搜索词（发给站点） | `search_keyword(number, site=…)` | `FC2_DIGITS_SITES`（当前只有 supjav）里的 FC2 → 只发数字后缀 |
| 复核词（认结果） | `match_token(number)` | FC2 → 数字，带词边界；其它 → 完整番号 |

实测（2026-10-24）：`FC2-PPV-1631136` → Supjav 命中 1 条
`FC2PPV 1631136 …` 分类 `Uncensored JAV`，判定"确有 0.9"，
链接 `https://supjav.com/44569.html`。

### 2. 搜索词被过度归一化（排查 FC2 时顺带发现，影响所有番号）

`normalize_number()` 会去掉分隔符：`IPX-123` → `IPX123`。原实现直接把归一化结果
当搜索词发给站点，而站点搜索框认的是 `IPX-123`。现在搜索词保留规范写法
（`parse_number().number`），复核仍用归一化值。

### 3. 替换入口位置错误 → 流程顺序修正（用户报告）

原流程：检查页「将选中视频加入版本管理」→ 直接跳版本管理，**跳过了"有没有无码版"这一步**。

现流程：

```
检查页（可按喜欢/结论筛选 → 多选）
   └─[送去查无码版]→ 找无码版页（只查这些）→[送去替换]→ 视频版本管理（配对/快照/替换/核验）
```

- 检查页按钮改为「**送去查无码版**」，发 `events.release_lookup_requested`
- 找无码页新增「**送去替换**」，发 `events.media_upgrade_requested`
- 两者都**只传数据**：不调用对方的内部实现，替换逻辑全部留在版本管理模块

### 4. 缺少"手动挑一部分去查"的通道（用户报告）

**根因**：找无码页的清单来源是 `confirmed_censored()`（全部已确认有码），检索按钮
作用于整张清单，没有"只处理子集"的入口。

**修复**：`CensorReplacePage.receive_requests(paths)`：
- 把送来的路径映射成番号，存进 `_focus_numbers`
- `lookup_targets()` 只在 focus 内取目标；清单本身仍显示全部
- 「显示全部」按钮清除限定
- 刷新完成后**自动开查**这一批（用户在检查页挑完才送来，意图明确）

**为什么不在找无码页重做"喜欢/结论"筛选**：检查页已经有这些筛选，并且带
Jellyfin 账号状态快照（`library_review`）。再实现一遍就是两套逻辑、两个口径 ——
用户要的是"把我挑的拿去查"，不是"再给我一个筛选器"。

### 5. 测试引用已改名的方法（自查发现）

`tests/test_jellyfin_review_ui.py` 仍在调 `page._send_to_versions()`（已改名），
且断言的是旧流程（直接发替换请求）。已按新语义改写为 `_send_to_lookup()` +
`release_lookup_requested`。

## 二、审计结论（有实证的部分）

| 检查项 | 方法 | 结论 |
| --- | --- | --- |
| 跨页事件是否都有接收方 | 对比 16 个 `Signal` 定义与 emit/connect 集合 | 全部有发出方与接收方，无死信号 |
| 按钮是否连到不存在的方法 | 构造全部页面（`test_gui_smoke` 覆盖 `register_page` + 导航） | 构造期即执行 `connect`，全部通过 → 无死按钮 |
| 打开找无码页是否会自动全量检索 | 读 `_auto_paths` / `_auto_numbers` / `showEvent` | **不会**。`showEvent` 只 `refresh()` 读库；自动检索只针对 `_on_censor_changed` 刚确认的项 |

> 说明：曾尝试用正则静态扫描 `connect(self.X)` 找缺失方法，但 `connect(self.log_panel)`
> 这类是**连对象**（对象本身带槽），误报率极高，已放弃该方法，改用"构造期实测"。

## 三、待办（按优先级，需下一轮确认）

| 优先级 | 事项 | 现状 | 建议 |
| --- | --- | --- | --- |
| P0 | 找无码页内的"喜欢"筛选 | 只能靠检查页筛完送来 | 若要页内筛选，应复用检查页的 `library_review` 快照服务，不要再写一套 |
| P1 | 批量检索无确认 | 「检索未查与过期」对整张清单生效，200+ 项会一次打出大量请求 | 目标数 > 20 时弹确认，或批次化 |
| P1 | 两个"替换"页面命名易混 | 「找无码版」(`censor_replace`) vs 「视频版本管理」(`replace`) | 前者可改名为「查替换」或「无码核查」，后者保持 |
| P2 | FC2 检索耗时长 | 实测 72.7s（javdb/javbus/supjav + 索引全跑） | FC2 属天生无码厂牌，可短路索引环节；或对已 `confirmed` 的来源提前收敛 |
| P2 | 检索结果缺"去重/合并"视图 | 同一作品多个来源各一条候选 | 表格按番号分组显示，来源作为列 |
