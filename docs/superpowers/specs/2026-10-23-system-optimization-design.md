# 检测、检索及工具箱协同改造设计

日期：2026-10-23。状态：**用户已批准方案 B；已实施，最终结果与裁决见 ../../系统优化验收-2026-10-23.md**。

依据：`docs/系统审计-2026-10-23.md` 和离线复现脚本。当前基线为 v3.19.3 / `a4e2b3b`。

## 1. 目标与实施方式

用户要求遍历整个软件，对不可用功能、平行实现、bug、操作逻辑、缺失能力、UI 自定义、跨功能联动与扫描效率逐项处理。

本设计采用“保留现有模块、按完整使用场景逐阶段修复”的方式。检测、检索和替换继续分为各自的工作区，共用文件/作品身份、队列、任务记录和事件。用户现有数据和手工判断保留，并通过文件版本核验决定其是否仍有效。

默认由当前会话在当前目录逐阶段执行。每阶段修复、验证并更新问题状态；不为了重构而整体重写工具箱，不自动连接用户服务器执行媒体写入。

## 2. 可选方案及选择依据

| 方案 | 收益 | 代价 |
|---|---|---|
| A 只补已复现 bug | 最快恢复核心可用性 | 协同、自定义和性能仍分裂，后续容易再加平行逻辑 |
| **B 按场景修复并收敛公共契约（建议）** | 能处理八项要求，沿用已有工具/回滚/测试基础，每阶段可独立验收 | 需要同时维护数据迁移与跨页事件，范围比补丁更大 |
| C 整体重写 | 有机会统一全部交互 | 丢失现有边界处理，重新验证 19 个页面和媒体事务的成本高 |

建议 B；其中第一阶段先处理核心 bug，后续阶段扩展闭环，避免新能力建立在错误缓存与状态之上。

## 3. 核心领域契约

### 文件、作品、候选分别标识

- `FileRef`：规范路径 + 版本身份 + 可选库条目 ID/本地映射。只在文件版本匹配时采用人工结论。
- `WorkRef`：规范作品键与供站点检索的显示番号分别保存。作品级检索缓存可以在多个文件副本间共享。
- `ReleaseCandidate`：站点/条目键、作品匹配结果、版本种类、证据等级、入口与可用磁链。每条磁链所属版本必须可判断，不能因同作品有一个无码候选就把所有磁链当成无码。

像素化检测继续报告文件画面结构；检索报告外部作品版本。二者不能互相覆盖结论。替换产生新文件版本，必须验证新文件，不把“来自无码条目”自动记为“画面人工确认无码”。

### 结论与执行状态分离

保留 `Availability` 的确有、疑似、未见、未知语义，新增独立的执行状态：排队、运行、完成、部分完成、失败、取消。具体枚举和与 `ProcessingStatus` 的共用程度在实现中按现有 API 兼容决定。

规则：

1. 取消不覆盖成功缓存，任务仍可续跑。
2. 网络失败可保存尝试记录，但不成为正常长时效结论；使用短重试期限与失败类别。
3. 只拿到部分来源时保留已获得证据和来源缺口。正面确证可以保留；“未见”必须说明检索范围，不表示互联网不存在。
4. 构造失败、被拦、空响应、解析失败、无结果、禁用和无番号分别报告。
5. 普通标题为软线索，站点结构化字段为更强证据；否定词和番号不匹配会阻止正面结论。

### 缓存与配置

- 检测签名只包含实际影响结果的参数；并发、展示、主题不使检测失效。
- 检索签名包含源/解析器版本、有效来源设置和影响候选的参数；连接设置变化应重建传输，不把临时失败长期钉死。
- `cached()` 的“历史记录”和“可复用报告”通过命名/返回结构明确区分，UI 不能自己用 `report is None` 代替新鲜度判断。
- 每个任务启动时创建有效配置快照，运行期间不随设置页的对象赋值变化。
- 设置对话框编辑副本，保存成功后广播一次配置变化；取消编辑不会偷偷修改内存配置。
- 旧记录按 schema 迁移；无文件身份的人工记录保留为历史待核验。错误缓存可隔离重建，单条坏数据不使整页初始化失败。

### 共同任务与调度

检测与检索均注册到 `TaskManager`，使用已有 owner/resource 约束。检索是独立只读任务，不应阻止其他页面的读取和扫描；与媒体写入的资源冲突以真实目标路径为依据。

请求预算属于一次作品查询，host 限速器属于传输会话。每个实际网络尝试（包括重试/回退）经过限速与预算。并发前先实现线程安全的 host 排程与请求计数。

取消要求：停止新增作品/来源/重试，打断限速和退避等待；进行中的网络 I/O 有明确超时与任务状态，不能宣称 urllib 阻塞读可以瞬间取消。若要更强取消保证，采用可中断传输适配器并单独验收。

## 4. 用户流程与缺失能力

1. 从文件、文件夹或当前媒体库范围导入；显示不可访问/无映射条目及原因。库范围复用现有 `library_source` 和 `library_scope`，不再自行扫描服务器。
2. 检测页边扫描边显示结果，可筛选、查看证据、深入检查；人工判断可撤回并保留版本化历史。
3. 人工确认有码后通过统一服务发事件并入检索队列。启用自动检索时开始只读任务；关闭时等待用户手动执行。
4. 检索页提供“未查与过期”“失败重试”“所选重查”；每项显示状态、证据、来源健康与最近查询时间。失败不归为“未见”。
5. 候选提供打开条目和明确标注版本的磁链。默认复制经过匹配的无码候选；查看普通版本不与“找替换”的默认动作混淆。
6. 下载后的本地文件由用户导入，按作品键、时长、轨道与副本选择生成配对计划。复用 `utils.replacement` / `file_ops` 的校验、备份、回滚和任务中心恢复。
7. 替换完成发布 `media_changed`，旧检测身份失效，按配置安排新文件验证；NFO/服务器同步的结果分开显示，不能因同步失败掩盖文件已替换。
8. 自动化工作台增加检测与检索步骤，使用上述共同服务/队列/范围；媒体写入沿用现有计划审阅流程。

新增能力以这些已明确的场景为范围，不据此引入下载器账号管理或额外视觉模型依赖。

## 5. UI 与可自定义项

公共工作区偏好独立存储，不进入算法签名。优先使用项目已有配置/JSON 原子写工具，不另引入一套无关存储。

- 两个核心页共用可恢复的 splitter，支持调整左右比例；小窗可切上下布局。
- 列显隐、列序、宽度、排序与筛选可保存，可一键恢复默认。数字列使用真实数值排序。
- 状态批量更新时先冻结排序，以稳定作品键定位；恢复排序后保持选中项和滚动位置。
- 主工具栏保留“添加/开始/停止/检索所选”等主要动作，次要动作进入菜单；窄窗口可换行。
- 证据画廊按可用宽度自适应，提供图片尺寸/列数选择；复核按钮在证据区域附近保持可达。
- 字体大小、行密度、自动下一条、快捷键和提示显示可调整；控件有键盘焦点与可读名称。
- 检索网络与来源设置移到检索工作区和全局设置的共同部件，扫描设置仅保留检测参数。
- 状态颜色使用 theme token，切主题时现有行也更新；颜色不作为状态唯一表达。
- 标记、检索、替换三类进度分开显示，通过相同作品/文件入口跳转相关记录。

小窗验收以实际控件边界、滚动、按钮可点击为依据，不凭截图观感宣称通过。字体和缩放使用 100%/125%/150% 检查。

## 6. 性能设计与评估

先解决不必要的工作，再优化计算：

- GUI 不直接批量读文件/校验摘要。后台批量校验，分页/增量返回列表，并检查请求版本避免陈旧回填。
- 数据库对一批作品/文件使用批量读取；统一连接生命周期与事务，避免每行重新开 WAL 连接。
- 原始帧使用有界队列边取边分析，维持准确覆盖计数；只保留必要证据或受控暂存，不把整个 600 帧列表长期保留。
- 对抽样方式做同输入 A/B 基准，比较进程复用、分段解码、证据图批量输出；保留精确时间戳与独立帧判据。
- 并发由 CPU、内存预算与磁盘类型限制，先保守默认，再提供配置。不同 host 可并发，同 host 维持速率限制。
- 缩略图清理只回收未被当前有效报告引用的文件，失败/取消产物可回收；提供容量统计与清理入口。

基准记录：冷/热缓存耗时、首条结果延迟、每分钟文件/有效帧、峰值内存、子进程数、取消后的新增工作、命中/失效比例。短合成片只验证机制；真实长影片与 NAS 场景需要单独、可重复的测试输入后才能给出速度结论。

图像阈值改动必须同时跑未缩放与线性缩放样本，区分候选召回、强命中和复核量；不靠降低取样数量或把不确定结果改成确定来体现“优化”。
