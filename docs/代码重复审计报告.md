## A. 附属文件判定 —— 三套词表，同一文件可能得出不同结论 🔴

| 实现 | 位置 | 依据 |
| --- | --- | --- |
| `is_junk_attachment_path` | `utils/library.py:286` | `AUXILIARY_STEMS` + 正则 + 路径段（v3.8.2 我扩展过） |
| `is_auxiliary_media` | `utils/merge.py:891` | `AUXILIARY_WORDS` + `AUXILIARY_MULTIWORD` + `AUXILIARY_PATH_KEYWORDS`（**另一套词表**） |
| `is_junk_item` | `utils/scoring.py` | 基于 `Item` 对象 |

**风险**：两份词表内容不同（例如 `sample` 在 merge 里有、在 library 的精确匹配里没有），
同一个文件在两个页面可能被判成不同结果 —— 这正是「视频有码检测没问题、
字幕检测却把 theme/trailer 收进来」的直接原因。

**建议**：以 `utils/library.py::is_junk_attachment_path` 为唯一实现，
`merge.is_auxiliary_media` 改为**委托**并把差异词条并入同一份词表；
`scoring.is_junk_item` 在拿到 Item 后转调路径版，保证一致。

**已加守则**：`tests/test_architecture.py::test_auxiliary_rules_are_defined_once`
（现在是 xfail，合并后会变成硬断言 —— 治理完把它改掉）。

## B. 扩展名清单 —— 5 处各自定义 🔴

| 定义 | 位置 | 说明 |
| --- | --- | --- |
| `video_extensions` / `subtitle_extensions` | `config.py` | **唯一事实来源**（用户可在设置里改） |
| `VIDEO_EXTENSIONS` | `utils/merge.py:23` | 另抄一份 |
| `SIDECAR_EXTENSIONS` / `SUBTITLE_EXTENSIONS` | `utils/merge_archive.py:34,38` | 又一份 |
| `_COVER_EXT` | `utils/library.py:242` | 封面用 |
| ~~`_AUDIO_EXTS`~~ | `utils/whisper_tool.py:48` | **已删除**（v3.8.4 后成为死代码） |

**风险**：用户在设置里加了 `.webm`，只有走配置的那一半功能会跟着变，
另一半（merge / merge_archive）仍旧不认 —— 表现为"有的地方认、有的地方不认"。

**建议**：新建 `utils/media_types.py` 提供 `is_video()` / `is_subtitle()` /
`is_cover()`，内部**默认读配置**、允许调用方传入覆盖；以上各处常量逐步改为引用它。

**已加守则**：`test_video_extensions_come_from_config`、`test_no_dead_extension_constants`。

## C. 目录扫描 —— 8 处各写一遍 🟠

`workers/scanner.py:60`、`utils/merge.py:918`、`:1105`、
`automation/orchestrator.py:102`(os.walk)、`:149`、`:163`、
`ui/pages/censorship.py:49`、`:72`、`ui/pages/lada.py:524`、
`ui/pages/subtitle_gen.py`（`_add_paths`）。

**差异（这才是危险的地方）**：

- `scanner.py` 有 **>240 字符路径跳过** + `OSError` 兜底（无权限/超长不崩）；
- 其余多处**没有** → 遇到长路径或无权目录会抛异常或漏文件；
- 每处的扩展名过滤、去重、排序规则各不相同。

**建议**：抽 `utils/file_scan.py::iter_media_files()`，统一"扩展名过滤 + 跳过附属 +
长路径保护 + OSError 兜底"，所有页面/ worker 复用（worker 版加暂停/进度回调即可）。

## D. 取文件名 —— 2 套，其中一套有已知坑 🟠

- `utils/library.py:245 split_path_name()`：同时认 `/` 和 `\`（因为库里的路径
  可能是另一个平台写下的，POSIX 的 `basename` 不认反斜杠，会把整串当文件名 →
  附属判定/封面查找全部失效）。注释里明确写了这是实测出来的。
- 但下面这些地方仍直接用 `os.path.basename`：
  `utils/merge.py:280`、`:894`、`utils/merge_repair.py:276`、
  `ui/pages/censorship.py:94`、`:207`。

**建议**：统一改用 `split_path_name`（或至少在涉及"库里存的路径"的地方用它）。

## E. UTF-8 输出保护 —— 5 份几乎相同的实现 🟡

`utils/console.py:33`、`scripts/release_flow.py:62`、
`scripts/release_notes.py:53`（内联）、`scripts/version_manage.py:57`（内联）、
`scripts/patch_whisper_encoding.py:24`。

**成因**：以 `python scripts/x.py` 运行时 `sys.path[0]` 是 `scripts/` 而不是仓库根，
`from utils.console import ...` 会失败 —— 我因此**在三个脚本里各写了一遍**，
还在注释里互相提醒"别依赖 utils.console"。

**问题**：提醒写在注释里没用，下一份照样会写第四遍，而且行为可能漂移
（其中一份漏了 `errors="replace"` 就会在中文控制台下崩）。

**建议**：`scripts/` 下的入口统一先做 `sys.path.insert(0, 仓库根)` 再复用
`utils.console.force_utf8_stdout`；确实要独立运行的脚本，至少把注释指向唯一实现。

## F. ffprobe 探测 / 时长校验 🟡

- `utils/lada_tool.py:378 validate_output_timing()`（内部 `_video_duration`）
- `utils/merge.py:53` 探测结构

两处都在调用 ffprobe 并解析 JSON 里的 duration，参数与解析逻辑重复。
**建议**：抽 `utils/probe.py::video_duration()`，两处共用。

## 治理顺序建议

1. **A（附属判定）** —— 已经让用户踩过两次，优先合并为一份。
2. **B（扩展名）** —— 建 `utils/media_types.py`，先把"视频/字幕"两件统一。
3. **C（扫描）** —— 抽 `utils/file_scan.py`，顺带把长路径/权限兜底补齐。
4. **D / E** —— 小改动，低风险，可穿插做。
5. **F** —— 影响面最小，最后做。

## 防御措施（已落地）

新增 `tests/test_architecture.py`：用**源码扫描**钉住"同一件事只允许一处实现"，
包括：

- 禁止再出现「自己拼 `splitext` + 字幕扩展名」的字幕判定；
- 附属判定词表只允许一份（现在是 xfail，治理后转硬断言）；
- 禁止死代码常量复现（`_AUDIO_EXTS` 已删）；
- 视频扩展名必须来自配置。

这类测试不会验证功能，但能让"又写了一处"在 CI 上直接变红 ——
因为重复实现本身从不引起测试失败，只会让同一个 bug 被用户报第二次。
