# 有码检测：设计、实测与扩展指南

> 对应版本：v3.14.0
> 代码位置：`censor/`（纯 Python，不依赖 Qt）
> 界面：`ui/pages/censorship.py`

---

## 1. 为什么推翻旧实现

旧版「视频有码检测」页只有一条规则：文件名里有没有 `fc2` / `无码` / `-U` 之类关键词。
它有两个绕不过去的问题：

1. **文件被换成无码版之后，文件名往往没改** —— 判成"有码"，得人肉核对；
2. **刮削标签描述的是"这部作品"，不是"这个文件"** —— 作品有码不代表手上这份还有码。

于是 v3.14 把"结论"和"依据"拆开：结论只有三态，依据逐条列出来源与置信度，
冲突时**以画面为准**（因为用户真正不信任的正是元数据）。

## 2. 分层

```
censor/
├── models.py       领域模型：Evidence / Verdict / FrameCandidate / VideoVerdict
├── numbering.py    番号解析（纯字符串，CI 上跑满用例）
├── registry.py     插件注册表（detectors / sources 两张表）
├── base.py         BaseDetector + ProbeContext
├── file_signals.py 文件名 / NFO / 服务器标签 / 番号系列（便宜的先跑）
├── mosaic_cv.py    画面网格检测（numpy，最贵，放最后）
├── fusion.py       证据融合 → 结论（"检码宪法"写在这）
├── store.py        SQLite 结果缓存 + 人工标注表
└── service.py      编排：缓存 / 取消 / 批量
```

依赖方向严格单向：`models ← numbering ← base ← {file_signals, mosaic_cv} ← fusion ← store ← service ← ui`。
`censor/` **不 import 任何 Qt**，所以能在无显示器环境（CI）里全量测试。

## 3. 画面检测算法

### 3.1 判据

日本 AV 的马赛克本质是 **等宽正方形网格 + 块内被抹平 + 块边界有台阶**。
在局部窗口里，沿 x 方向的阶跃曲线 `|∂g/∂x|` 应该长成"每 N 像素一个尖峰、尖峰之间几乎平"的
周期性阶梯。

实现（`mosaic_cv._best_grid`）：

1. 取 160×160 窗口的阶跃**矩阵**（保留逐行，不压成一维）；
2. 把每行按候选周期 N 折叠成 N 个余数类；
3. 若某个余数类吃掉了绝大部分阶跃能量（**对齐率**高），
   且边界能量远大于块内能量（**比值**大），就是网格；
4. 两个方向都要成立、周期一致，才算命中；
5. 逐行判定后取中位数 —— 半覆盖窗口不会被整体拖死。

### 3.2 为什么保留逐行

第一版把窗口压成一维平均曲线，结果：合成马赛克 10⁶ 分，但只覆盖窗口 70% 的真实马赛克
被 30% 的正常纹理稀释到 **10 分**。改成逐行 + 中位数后恢复到可判别区间。

### 3.3 三个必须处理的坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 黑边 | `scale+pad` 补的纯色区，整窗近常数 → 比值爆炸 | 按行/列标准差裁出真实画面区（`_content_bounds`）+ 跳过 `std < 4` 的窗口 |
| 周期约数 | 真周期 16 时，8 同样完美对齐 | 分数接近（≥98%）时取**更大的周期** |
| 大周期假命中 | N=38 时窗口只排得下 4 个块，统计不可靠 | `min_chunks=5`：排不下 5 个块直接不参与 |

### 3.4 合成样本验证

给真实无码帧原地打块平均马赛克（与日本 AV 的打码方式一致），对比检测结果：

| 样本 | 块边长 | 得分 |
| --- | --- | --- |
| 原始纹理 | — | 0 ~ 1.5 |
| 打码（N=16） | 16 | > 32（命中 `strong_score`） |
| 打码（N=24） | 24 | > 32 |
| 加黑边 | — | 不命中 |
| 纯色帧 | — | 0 |

### 3.5 真实片源实测（本机 4 部，60 帧抽样，960×540 分析）

| 片 | 实际 | 最高分 | 判定 |
| --- | --- | --- | --- |
| PIYO-170 | 有码 | 33.5（块边长≈14px @ 00:53:53） | **自动判有码** ✅ |
| TYOD-360 | 有码 | 27.8 | 未定（差 4 分到阈值）→ 进复核 |
| NCRA-026（无码流出） | 无码 | 31.3 | 无码（画面未过阈值，标签支持） |
| STARS-016-U | 无码 | 0.0 | 无码 ✅ |

**结论：检出力真实存在，但不足以单独裁决。** 所以设计上：
画面高分才自动判"有码"，其余一律进人工复核队列，按分数从高到低排。

已知会拉高分数的情况：AI 破解（Lada）残留的网格伪影、低码率老片、
周期性纹理强的背景（百叶窗、格纹衣物）。这类会落到复核队列，需要人点一下。

## 4. 抽帧：为什么是 30 秒

3.6 小时 / 6.8 GB 片源，机械盘实测：

| 做法 | 耗时 | 结论 |
| --- | --- | --- |
| `-vf fps=1/N` 全帧解码 | 十几分钟 | 不可用 |
| `-skip_frame nokey` 只解 I 帧 | 约 31 秒 | **采用** |
| 逐点 `-ss` seek（60 次） | 约 26 秒 | 略快但机械盘随机 seek 更不稳 |
| 分 8 段 `-ss` + `-skip_frame` | 约 31 秒 | 无收益（每段仍扫 1/8 全片） |

瓶颈是"关键帧解码"本身，约 **9 秒/小时片长**，改 ffmpeg 参数榨不出更多。
所以整库速度靠**上层多路并行**（默认 4 路）：745 部约 1 小时。

分析分辨率取 960×540：1280 的管道开销翻倍（67s vs 33s）而精度提升有限；
再往下会让 1080p 的 20~40px 块缩到 8px 以下，直接漏检。

## 5. 融合规则

按顺序裁定，命中即返回：

1. **人工确认** → 直接采信，`confidence=1.0`。算法永不推翻。
2. **画面检出马赛克**（≥0.6）→ 有码。若与番号/标签的无码标记冲突，标记"建议核对"。
3. **番号属于天生无码厂牌**（FC2 / HEYZO / 1pondo / Caribbean / Tokyo-Hot …）→ 无码，0.8。
4. **作品库显示该番号无码发行** → 无码，但**仍标记待复核**（作品级事实 ≠ 这份文件）。
5. **只有标签/文件名说无码** → 无码 0.5，强制待复核。这正是历史误判的来源。
6. 其余 → 未定，进复核队列。

各来源的置信度**上限**写死在 `models.EvidenceSource.ceiling`，弱信号无法自称很确定。

## 6. 缓存与人工标注

- `censor_probe` 表：以路径为主键，**有效性 = (size, mtime)**。文件被替换过自动失效重算。
- `censor_label` 表：人工结论，独立存放。`clear_probes()` 不会清它 ——
  它是将来调阈值、换模型的**语料**。

## 7. 怎么加一种新的检测方式

```python
# censor/my_detector.py
from censor.base import BaseDetector, ProbeContext
from censor.models import CensorState, Evidence, EvidenceSource

class MyDetector(BaseDetector):
    name = "visual.my_detector"
    title = "我的新检测器"

    def available(self):
        return True, ""

    def detect(self, ctx: ProbeContext) -> list[Evidence]:
        return [Evidence(EvidenceSource.VISUAL, CensorState.CENSORED, 0.9, "命中理由")]
```

在 `censor/__init__.py::register_builtins()` 里加一行：

```python
detectors.add("visual.my_detector", MyDetector, priority=95, title="我的新检测器")
```

UI、缓存、融合**都不用改**。配置里 `censor_detectors` 名单控制是否启用。

接"无码资源检索源"同理，用 `sources.add(...)`。

## 8. 下一步（未做）

### 8.1 无码资源检索（需求第二部分）

已实测确认可行：

- **JavDB 可直连**（200，服务端渲染，可正则解析）：番号 / 片商 / 系列 / 類別 / 時長 / 演員。
- **判定"作品是否存在无码版"的可靠信号**：`片商` 字段。实测 `NCRA-026`（用户的
  【无码流出】版本）片商 = `日本コンテンツ流通`（流出版发行商），而
  `PIYO-170`（有码）片商 = `ひよこ`。配合 `/makers/uncensored`、`/tags/uncensored` 可建厂牌表。
- JavBus 返回 302、7mmtv 不可达、sukebei 超时 —— v1 不应依赖，走插件化按需接入。
- 检索结果模型可直接复用 `sources` 注册表 + 一个新的 `ReleaseCandidate` 数据类，
  与现有「破解视频替换」流程串起来（找到 → 下载 → 替换 → 自动改标签）。

### 8.2 提升检码准确率

1. 用复核产生的标注集（`censor_label`）评估当前阈值的精确率/召回率；
2. 按标注集调 `censor_window` / `min_ratio` / `strong_score`，或换窗口尺度（大块用 240 窗口）；
3. 若仍不够：接本地视觉模型（Ollama 视觉模型看候选帧）或 NudeNet 定位生殖部位后
   在该区域内做网格验证 —— 两者都能作为新检测器插进来，不动主流程。
