# 像素化任务、缓存与复核

## 页面操作

顶部保留添加文件、添加文件夹、更多和停止。进度条独立显示，分为发现文件、读取线索、分析视频、完成/部分失败/已停止。目录发现时总数尚未知，显示活动进度条；进入分析后显示完成数/实际检查总数、复用分析数、失败数和延后数。下一行显示正在处理的视频及其取样、画面分析或证据图生成进度。任务中心使用同一份阶段和计数，而非从日志猜测。

扫描期间可以滚动表格、切换筛选、选择已完成结果并放大证据；输入、检查设置和人工确认暂时锁定，避免修改正在运行的请求。结果按批回填，保持当前选择。进度通知节流，避免大量缓存结果造成任务中心反复重建。

更多菜单集中放置继续未完成、重试失败、选择延后视频、历史记录、检查设置、帮助和清空列表。“此视频”菜单提供3倍采样深入检查。

表格的主线是四列：**文件名 / 结论 / 处理 / 无码版**（外加记录来源）。结论与处理是两个独立维度，
筛选也只剩「视图 × 结论」两个下拉，完整定义见[像素化状态与工作流](像素化状态与工作流.md)。

## 重新导入时究竟跳过什么

“分析完成”只表示这次程序处理成功，不表示已经人工复核，也不证明视频没有问题。

| 文件状态 | 再次导入的处理 | 复核状态 |
| --- | --- | --- |
| 已成功分析，文件身份、配置、算法与相关输入不变 | 复用有效分析，免去重复抽帧；表格显示“复用分析” | 自动疑似项继续待复核，不会因复用消失 |
| 已人工确认，当前文件身份匹配 | 保留该文件版本的人工确认 | 人工已确认 |
| 文件被替换，或配置/算法/NFO等分析输入改变 | 缓存失效，按当前条件重新分析 | 依据新证据重新分流；替换文件不继承旧确认 |
| 失败、取消、部分完成 | 不作为可复用的成功分析，恢复或重试 | 单独显示处理状态 |
| 名称/NFO有明确无码或破解线索 | 默认延后 | 仅手动勾选后检查，普通队列完成不自动放行 |

例如导入2000部，程序检出500部疑似像素化但你没有复核：再次导入时，这500部**连扫描队列都不会进**
（有效结果直接铺回列表并标注“复用分析”），但它们仍然是500部待复核。不会自动变成人工确认，也不会当作“已经没有问题”从表格删除。分析得到抽样低风险的项目单列，仍非全片不存在的证明。

更多 → 历史与重新分析 → 忽略缓存，重新分析可见的未复核项，可以强制重算当前筛选下的未复核项目；默认排除人工确认与名称延后项目。单条深入检查也忽略缓存，并保留已有人工确认。

## 打开页面会自动接上待办

进入页面时先读一次数据库里的待处理项（最多 300 条），把它们铺进列表并把视图切到
「待我处理」，状态栏写明载入了多少。以前要手动「更多 → 加载历史记录」，
关一次程序待办就等于丢了。想从零开始可以点「清空当前列表（保留记录）」。

## 历史记录的边界

加载历史在后台读取，分批显示，记录来源为“历史快照”。加载不会批量访问远程视频或NFO，因此这些快照尚未验证当前文件是否被替换。重新添加文件时才进行身份与分析签名校验。历史中的人工结论属于当时的文件版本，保存新的人工确认前仍校验当前文件身份。

文件身份使用大小、纳秒修改时间以及头/中/尾分段摘要，不能发现所有保持大小和时间不变的局部编辑；需要时可手动忽略缓存重算。恢复粒度为文件：已完成且有效的分析复用，中断的文件重新检查。历史目前保存每个路径最近成功的分析与版本化人工记录，不是每次扫描的完整快照。

后台回填的旧结果不会覆盖本会话刚保存的同版本人工结论；未知文件身份的取消/失败结果不会继承旧确认。清空列表只清视图，不删除历史、人工记录或媒体文件。
