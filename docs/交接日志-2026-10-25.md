## 0. 先读这三段

### 0.1 项目是什么

JellyfinToolkit 是 PySide6 写的本地媒体工具集，核心是三条链路：

```
① 视频像素化检查（判定有没有码）
      ↓ 人工标记「有码」
② 找无码版（Supjav / JavDB / JavBus 检索 + 下载）
      ↓ 确认有无码版
③ 视频版本管理（配对 / 快照 / 转封装 / 替换 / 核验）
```

三条链路**必须分开**。这段时间里反复出现的 bug，一半是"链路之间互相串了"。

## 2. 逐版本详解

### 2.1 v3.19.0 — 找无码版独立成页

**问题**：检查页既做判定又做检索，两个阶段的按钮/状态混在一起；用户标记后不知道下一步去哪。

**改法**：

- `ui/pages/censor_replace.py`（找无码版）独立成页，数据只来自 `VerdictStore.confirmed_censored()`——**真人标记过的**记录，算法猜的不进。
- 检查页瘦身成 `文件名 | 结论 | 处理 | 记录来源`，标记只**入队**（`ReleaseService.queue`），不联网。
- 证据图从"一图一按钮"改成平铺网格，点图放大。

**坑**：第 0 列被设成 `Stretch`，宽度锁死——而它恰好是最该拖宽的列。**所有列的 resize mode 都改 `Interactive`，让最后一列吃剩余空间**。

---

### 2.2 v3.19.1 — 启动失败不再静默

**问题**：双击没反应，只弹 `Application Error 0xc0000142`。

**根因**：`main.pyw` 走 `pythonw.exe`（无控制台），启动期异常直接吞掉。另有 `start.bat` 用 `where python` 取 PATH 第一个——本机 PATH 首位是某个工具自带的隔离运行时（没有 PySide6）。

**改法**：

- 启动前单独 `import PySide6` 试导入，失败就弹窗说明"当前解释器没装 PySide6"并给出该用哪个；
- 任何启动期异常写 `data/startup-error.log` + 弹窗，**弹窗里带解释器完整路径**（这类问题九成是选错解释器）；
- `start.bat` 按固定顺序找解释器：项目 `.venv` → 常见安装路径 → `py -3` → 最后才 PATH，并且启动前验证 `import PySide6`；
- 新增 `启动.bat`（带控制台，出错不闪退）。

**结论**：`0xc0000142` 是当时那台机器的**瞬时环境问题**（杀软注入/DLL 冲突），不是代码缺陷。这一版没改业务代码，只补"失败可见"。

### 2.3 v3.19.2 — 批处理 CRLF/ASCII

**问题**：上一版带的 `.bat` 双击打不开。

**根因**：批处理必须是 **CRLF + 纯 ASCII**。写入时用了 LF 或包含中文，cmd 解析失败。

**改法**：所有 `.bat` 生成逻辑固定 CRLF、纯 ASCII；中文提示改成英文或放到 `.txt` 里。

---

### 2.4 v3.19.3 — 标记按钮点了没反应

**问题**：点「标记有码」没反应。

**根因（两个叠加）**：

1. 按钮被布局压成 **20px 高**，文字挤成一团；
2. 自动恢复待办后**列表有内容但没有选中行**，处理函数 `if self._current is None: return` 直接静默返回；
3. 标记后触发的检索异常**打断了后续刷新**，看起来像"没保存"。

**改法**：

- `setMinimumHeight(28)` + 最小宽度 104；
- 无选中时按钮**直接禁用**并提示"先选中一行"；恢复待办后自动选中第一条；
- 检索异常单独 catch，**绝不连累"标记已保存"这个事实**；
- 补右键菜单（标记/撤回/重新分析）。

**教训**：**"动作成功"与"后续副作用失败"必须解耦**。这条在 3.22.7 又踩到一次。

### 2.6 v3.22.2 — Supjav 抓不到信息（四个叠加根因）

**现象**：Supjav 源永远 403 / 超时，"YMDD-365 明明有无码版但查不到"。

**这是本项目最典型的"一个现象、多个根因"案例**，四个各自独立、单独都会让结果为空：

| # | 根因 | 你看到的现象 |
| --- | --- | --- |
| 1 | `detect_proxy` 对显式配置**不补 `http://`** | 填 `127.0.0.1:7897`（最自然的写法）时 urllib 静默直连 → 超时。这条让**填了代理等于没填** |
| 2 | 只认"系统代理" | Clash 常只开端口不开系统代理 → 判定无代理 → 直连被拉黑 |
| 3 | 站内必须**手动**点"连接 Supjav 浏览器会话" | 忘了点，Supjav 源就永远 403 |
| 4 | 页面完成判定**严格比较 URL** | Cloudflare 追加 `__cf_chl_rt_tk`，URL 永不相等 → 等满 45 秒超时 |

**改法**：

- 显式配置补 scheme；探测本机端口（连通即用，带缓存）；
- 检索前自动接上浏览器会话，窗口弹出但不抢焦点；
- 页面完成判定忽略 `__cf_*` 挑战参数。

**还有三个坑**：

- **窗口必须 `show()`**：不显示时 Chromium 节流 JS，CF 挑战脚本跑不完 → 页面永远空白；
- **`read()` 在后台线程碰 GUI 会崩**（`0xC0000005`）：显示窗口的动作移到 GUI 线程；
- **命名 profile + 自定义 storage 路径** → `loadFinished=False`、URL 始终为空。改用默认 profile。

**验证**：真实抓到 YMDD-365 的 `[Reducing Mosaic]` 条目，`https://supjav.com/256514.html`。

### 2.7 v3.22.3 — FC2 搜索词 + 流程归位

**问题 A**：Supjav 搜 `FC2-PPV-1631136` 返回 0 条（截图实证）。

**根因**：**搜索词与复核词是同一个值**。FC2 各站写法不统一（`FC2-PPV-x` / `FC2PPV x` / 纯数字），把整串丢给站内搜索常 0 命中。

**改法**（集中在 `censor/releases/base.py`）：

| 概念 | 函数 | 规则 |
| --- | --- | --- |
| 搜索词（发给站点） | `search_keyword(number, site=)` | `FC2_DIGITS_SITES = {'supjav'}` 里的 FC2 → 只发数字后缀 |
| 复核词（认结果） | `match_token(number)` | FC2 → 数字**带词边界**（`1631136` 不命中 `16311360`） |

**不要一刀切**：JavDB 用整串才准，用纯数字反而偏——所以按站点声明。

**顺带发现（影响所有番号）**：`normalize_number()` 会去掉分隔符（`IPX-123` → `IPX123`），而站点搜索框认带横线的写法。搜索词改用 `parse_number().number`（保留横线），复核仍用归一化值。

**问题 B**：替换入口放错页——检查页「将选中视频加入版本管理」直接跳版本管理，**跳过了"有没有无码版"这一步**。

**改法**：

```
检查页（筛喜欢/结论 → 多选）→[送去查无码版]→ 找无码页（只查这批）→[送去替换]→ 视频版本管理
```

- 检查页发 `release_lookup_requested`；
- 找无码页 `receive_requests(paths)`：用 `_focus_numbers` 限定检索范围，清单仍显示全部；
- 两页**只传数据**，配对/快照/替换全留在版本管理模块。

**为什么不在找无码页重做"喜欢"筛选**：检查页已有（且带 Jellyfin 账号状态快照），再实现一遍 = 两套口径。

**实测**：`FC2-PPV-1631136` → Supjav 命中 `FC2PPV 1631136`（分类 Uncensored JAV，确有 0.9）。

### 2.8 v3.22.4 — 判定放开 + 命名整理

**问题**：大量视频需要人工确认，而"确认压根不难"。

**根因（一行正则）**：

```python
# censor/tag_signals.py 旧逻辑
_CENSORED = re.compile(r"...|censored|mosaic|...")
classify_tag("[Reducing Mosaic]YSN-638")  →  (uncensored=False, censored=True)
```

链条：标题被判"有码" → `_detail` 里 `positive and not negative` 不成立 → **站内分类 `Reducing Mosaic` 的 0.9 依据被丢掉** → 只剩标题的 0.60 → 结论"疑似（需核对）"。

**改法**：新增 `version_level()`，四档：

| 档 | 命中 | 定档 |
| --- | --- | --- |
| `strong` | 无码/流出/破解/Uncensored/Decensored/Leak | 0.85（站内分类 0.92）→ 确有 |
| `soft` | **Reducing Mosaic**、减码、薄码 | **0.80**（= `HARD_EVIDENCE`）→ 确有 |
| `censored` | Censored、裸 Mosaic | 否 |
| `neutral` | **Chn Sub / English Sub / 4K / 60FPS / HD / VR** | 不参与判断 |

**`classify_tag` 保持不动**——检测链路（`file_signals`/`jobs`）还在用它，改了会连带影响。

**命名整理**（用户要求"简单可读，别搞拼接词"）：

| 位置 | 原 | 现 |
| --- | --- | --- |
| 页面 | 找替换 · 已确认有码 | 找无码版 |
| 按钮 | 检索未查与过期 / 检索所选 / 检索无码版 | 查询未查 / 查询选中 / 查询这条 |
| 按钮 | 打开页面 / 无磁链 / 检索设置… | 打开链接 / 复制磁链 / 设置… |
| 版本管理 | 保存继承快照 / 验证继承 / 载入上次快照 | 保存进度快照 / 核对结果 / 载入上次记录 |
| 统计行 | 9 段数字拼接 | 5 段（其余进 tooltip） |
| 结论 | 疑似（需核对） | 疑似 |

**实测**：`YSN-638` → `[Reducing Mosaic]YSN-638`（站内分类 Reducing Mosaic，0.85）→ **确有**（原"疑似需核对"）。

### 2.9 v3.22.5 — ambiguous 行可解决

**问题**：5 行就绪 + 1 行 ambiguous，**整批锁死**。

**根因**：

```python
ready = all(row.status == 'ready' for row in rows)      # 全部就绪
btn_prepare.setEnabled(ready ...)                        # 保存快照
btn_start.setEnabled(prepared_ready ...)                 # 替换还要求"已保存快照"
```

一行 ambiguous 就让「保存快照」永远灰着 → 替换永远灰着；而界面上**没有任何地方能解决那一行**——用户被要求"修改"却没有工具。

**改法**：

- **双击** ambiguous 行 → 候选菜单 → 选定后变「就绪」；
- **右键** → 「选择版本…」/「从配对里移除」；
- 状态列中文化（`ready/ambiguous/container_mismatch` → 就绪/要选版本/封装不同）；
- 「载入上次记录」没快照时给中文提示，不再抛 `[Errno 2] latest.json`。

**顺带纠正的概念错误**（很重要）：

```
preview_release_replacements 里：
  row['source']     = 新版本文件
  row['target']     = 被替换的原文件
  row['candidates'] = 匹配到的多个原文件
```

所以 `ambiguous` = **一份新版本匹配到多个原文件**（不是"多个新版本"）。

### 2.10 v3.22.6 — 跨封装替换

**问题（用户质疑）**："封装不同为什么就一定不能继续？只要文件能播放就该能换。"

**根因**：`execute_replacements` 是**原地替换**（把候选搬到原路径）。直接搬会把 mkv 内容装进 `.mp4` 名字里——Jellyfin 用 ffprobe 能探测播放，但**客户端直连/硬解按扩展名选解复用器**会失败。所以当初干脆判 `container_mismatch` 拦掉。

**改法**：

- 状态改名 `container_convert`（界面「要转封装」），**与「就绪」一样可直接执行**，不需要用户选；
- 执行前 `ffmpeg -c copy` 无损转成原封装（mp4 加 `faststart`），几秒、不重编码；
- **路径仍是原文件** → Jellyfin 条目/进度/收藏/NFO 全部不动；
- 转封装失败（如 PGS 装不进 mp4）明确报错并保留原件。

**关键细节**：转封装后 `expected_source_hash` 必须传 `None`，否则 `safe_replace` 报"源文件已改变"（原文件此前已校验过）。

### 2.11 v3.22.7 — 保存快照的两个死结

**问题**：点「保存进度快照」必然失败，然后被要求"重新预览"，再失败，**无限循环**。

**根因 2 个**：

1. **3.22.5 引入的死循环**：`_check_pairing` 保存前重新跑 `preview()`，逐字段比 `target`。手动选过的那行重新预览时仍是"多候选"（`target` 为空）→ 比对不等 → 判"计划已变化" → 死循环。
2. **缺 API Key 全阻塞**：`configuration_error` 在 `prepare` 里 `raise` → 每行 `blocked`。但它只影响**可选的用户状态继承**，不该挡住"换本地文件"。

**改法**：

- 选定打 `chosen` 标记，校验只要求"选定的原文件仍在候选里"；补齐 `target_identity`/`target_hash`；
- 缺 Key 降级为 `server=None` + `inheritance_note`，替换照常，界面写明"本次只替换本地文件"。

**顺带补完的事**：3.22.6 的转封装只改了 `execute_replacements`，而**版本管理页走 `MediaUpgradeService`**（另一条链），仍有独立的封装拦截。这次一并打通：

- `_check_files` 对 `convert_container` 放行；
- `prepare` 把 `container_convert` 当就绪；
- `execute` 在配对校验后、进循环前统一转封装，转完清标记（否则下层再转一次）。

### 2.12 v3.22.8 — Jellyfin 12 认证头

**问题**：地址和 API Key 都对，但连接失败。

**实测（用户真实服务器，Jellyfin 12.1.0）**：

| 认证方式 | 结果 |
| --- | --- |
| `X-Emby-Token: <key>` | **401** |
| `Authorization: MediaBrowser Token="<key>"` | **200** |
| `?api_key=` / `Bearer` | 401 |

**根因**：**Jellyfin 12 起不再接受 `X-Emby-Token`**。项目三处都用它（`media_server` / `jellyfin_api` / `library_api`），注释还写着"Jellyfin 保留了 Emby 的历史头名"——那是 10.x 的事。

**改法**：

- 新增 `auth_headers()`：**两个头一起发**（Jellyfin 认 Authorization，Emby 认 X-Emby-Token，服务端忽略多余的头）；
- `detect()` 给了 key 就额外请求 `/Users` **真验一次**（原来只查公开接口，key 错了也显示"连接成功"，到扫描才 401）；
- `http`↔`https` 填错自动换一种再试；
- 错误信息带完整地址与可执行建议，不再一律说"无法连接"。

**同时暴露的产品问题**：旧错误文案把 401/502 统一说成"无法连接（地址/端口是否正确？）"，**把排查方向带偏**。以后错误必须透出状态码。

### 2.13 v3.22.9 — 跳转、自动检索、窗口

**问题 A**：标记后不自动跳下一条。

**根因（第一层）**：`_advance_review` 除了 `needs_review` 还调 `_matches_filter`——而**表格本身已按视图筛过一遍**。用户的视图被记成「暂不处理」(parked)，`in_view(parked, 待复核)` 恒为 false。

**改法**：只看表格可见行 + 仅判 `needs_review`；**启动不再恢复视图**（固定从「待我处理」开始），其它筛选照常恢复。

**问题 B**：标记有码后自动联网检索 + 弹窗。

**根因**：`release_auto_lookup` 默认 `True`。改默认 **False**——标记只入队，去「找无码版」手动开始。

**问题 C**：Supjav 窗口没有最小化按钮。窗口 flags 加 `WindowMinimizeButtonHint`。

**同时产出**：`docs/检测与跳过逻辑-2026-10-25.md`（检测证据链、缓存复用条件、导入与历史的差异）。

### 2.14 v3.23.0 — 下一条永远回第一条

**问题**：不管从哪条开始，下一条永远是第一条。

**根因（3.22.9 只修了一半）**：

```
标记 → 当前行不再是"待复核" → 被筛掉（isRowHidden）
     → 可见行列表里找不到 after_path
     → positions.index() 落空 → start = 0
     → 从第一条开始找 → 跳第一条
```

**改法**：**用全量行（含被筛掉的）定位"我在哪"，再在可见行里往后找**，末尾绕回。

逻辑抽成纯函数 `censor/review_route.next_review_target(positions, visible, after, is_candidate)`，脱离 GUI 直接单测（8 项）。

**验证（真实库 + 合成 5 行，表格开启排序）**：

```
表格读出的行序是 E,D,C,B,A（排序后，不是插入顺序），隐藏其中一行：
  从 B(第4行) → A(第5行，绕回)      ✅
  从 A(第5行) → E(第1行，绕回)      ✅
  从 D(第2行) → C(第3行)            ✅
  从 E(第1行) → C(跳过被隐藏的 D)   ✅
```

## 3. 架构约定（后续改动必须遵守）

### 3.1 有三条链路，不要互相串

```
像素化检查 →（标记有码，只入队）→ 找无码版 →（确认有无码）→ 送去替换 → 版本管理
```

**跨页只传数据**（信号 + `receive_*` 方法），A 页不调用 B 页的内部实现。

### 3.2 有两套替换链，改替换行为必须两处都看

| 链路 | 入口 | 特点 |
| --- | --- | --- |
| 泛用替换 | `utils/replacement.execute_replacements` | 用于恢复/通用替换 |
| 版本管理 | `utils/media_upgrade.MediaUpgradeService.execute` | 带 Jellyfin 继承、快照、暂存校验 |

3.22.6 只改了前者，导致版本管理页仍拒绝跨封装——3.22.7 才补上。**这是本项目最贵的教训之一。**

### 3.3 搜索词 ≠ 复核词

- `search_keyword(number, site=)`：发给站点，可以放宽（FC2 → 数字）
- `match_token(number)` / `contains_number()`：认结果，必须严格（带词边界）

混用会导致"搜不到"或"误命中"。

### 3.4 判定分级与检测判定分开

- `version_level()`：检索源用，四档（strong/soft/censored/neutral）
- `classify_tag()`：检测链路用，回答"这个标签是否在说有码/无码"

**不要把 `classify_tag` 拿去做版本判断**——它把 `mosaic` 一律算有码。

### 3.5 术语（容易搞反）

```
source     = 新版本文件
target     = 被替换的原文件（路径不变）
candidates = 匹配到的多个原文件（ambiguous = 多个候选指向同一个新版本）
```

### 3.6 Jellyfin 认证

**Jellyfin 12+ 必须用 `Authorization: MediaBrowser Token="<key>"`**。
`X-Emby-Token` 在 12.x 返回 401。统一走 `utils/media_server.auth_headers()`。

### 3.7 "动作成功"与"后续副作用"必须解耦

标记保存成功，不能因为随后触发的检索/同步失败而显示失败。
这条在 3.19.3 和 3.22.7 各踩一次。

## 5. 排查工具箱（可复用）

### 5.1 用真实数据复现，别靠读代码猜

```python
# 把用户库复制到临时目录，环境变量指过去（BASE_DIR 会自动拼 /data）
src = Path(r'…\jellyfin-pixelation-implementation-v2\data')
root = Path(tempfile.mkdtemp()); (root/'data').mkdir()
for n in ('censor.db','config.json','workspace_preferences.json'):
    shutil.copy2(src/n, root/'data'/n)
os.environ['JELLYFIN_TOOLKIT_DATA_DIR'] = str(root)   # 注意：DATA_DIR = 这个 + /data
os.environ['JELLYFIN_TOOLKIT_OFFLINE'] = '1'
```

**"下一条永远第一条"就是这么找出来的**——读代码只能猜到 `auto_next`，跑起来才看到 `combo_filter` 停在 `parked`。

### 5.2 GUI 顺序类逻辑先打印实际值

表格 `setSortingEnabled(True)` 时，`item(r,0).data()` 的顺序是**排序后**的（实测 `E,D,C,B,A`）。
我第一版验证脚本按插入顺序写期望，误判成"还是乱序"。

### 5.3 `selectRow()` 之后谁在当"当前行"

`_on_row_selected()` 取的是 `_selected_visible_paths()[0]`——**行号最小**那条，多选残留时不是刚点的那行。

### 5.4 别用 `worker.wait()` 等 GUI 更新

会阻塞 GUI 线程，队列信号送不到，表格永远是 0 行。用 `qtbot.waitUntil`（内部 `processEvents`）。

### 5.5 环境变量覆盖不了 WorkBuddy 注入的代理

`HTTPS_PROXY=...` 行内赋值会被父进程注入覆盖，要用 `env -u HTTPS_PROXY -u HTTP_PROXY ...`。

### 5.6 沙箱限制

- 打包必须沙箱外（`dangerouslyDisableSandbox`）；
- 沙箱内 SQLite 写 %TEMP% 会随机 `readonly`（这也让我顺手修了产品层的开库兜底：`open_sqlite`）。

### 5.7 顺手修的产品级兜底（值得保留）

`censor/store.py::open_sqlite()`：

- `PRAGMA journal_mode=WAL` 失败 → 降级 DELETE 模式；
- 初始化时用 `BEGIN IMMEDIATE` 探一次真实写权限，**探测期间 `busy_timeout=0`**（否则遇到并发锁要等满 15 秒，直接把扫描拖到超时）。

## 7. 一句话总结

这 18 个版本的 bug，**八成不是"功能没写"，而是三件事**：

1. **两层过滤/两层校验**各自以为是唯一的（视图 + 表格、chosen + 重新预览）→ 死锁或跳错；
2. **一个现象多个根因**（Supjav 四个、FC2 两个）→ 只修一个还是不通；
3. **概念混用**（搜索词 vs 复核词、`classify_tag` vs `version_level`、两套替换链）。

接手时如果遇到"明明改了却没效果"，先问：**是不是还有第二条路径在做同一件事？**
