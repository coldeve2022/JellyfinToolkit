# 分组复核与人工标签同步（3.22.0）

本次针对本地文件复核工作量与人工结论联动。来源名称只选择检查策略，不证明画面内容；不访问影片检索站点，不下载媒体。

## FC2 分组现在怎样处理

在“像素化检查 → 检查设置”启用“分阶段取样”。默认分组前缀为 `FC2`，支持常见分隔形式和 `FC2PPV1234567` 等完整紧凑编号，也能添加其他前缀。仅识别文件名，不因父目录叫 FC2 就把其中所有文件归组。

完整默认计划为 60 个时段，首轮默认选择其中 30 个，分布到片头、片中、片尾。满足足够有效取样、不同画面数量、时间覆盖及低结构分条件，才进入“抽样低风险”，位于“暂不处理”，无需逐个加入当下的人工待办。

出现疑似网格、重复画面过多、取样不足或覆盖不够时，继续同一完整计划尚未解码的点。不会把先取的 30 个再解码一次。“深入检查”和“忽略缓存重新分析”绕过快速分流。原有成功缓存仍按当前文件身份和分析设置复用。

**低风险仍是“未定”，不是人工确认没有马赛克。** 它不会自动写确认标签，也无法保证短暂出现的区域一定被采到。没有按内容推断“哪些位置无关紧要”；对网格、字幕、水印等的语义判断仍需你确认。随时可选低风险视频补做完整检查。

## 更快进行人工确认

表格支持 Ctrl / Shift 多选。在“更多 → 批量人工确认”选择“有马赛克”或“未见马赛克”，查看数量和文件清单后确认。只处理当前筛选中可见的选中项；不会把所有低风险视频自动标记。每个文件会再次核验版本，替换或消失的文件单独失败，不影响其他项目保存。

批量操作在后台执行，可停止。已保存的确认保留；没处理的项目不会凭空确认。单项确认与原有快捷键、自动下一条继续可用。

## 人工确认自动联动 NFO 和 Jellyfin

在检查设置中分别控制 NFO、服务器同步及缺 NFO 时是否创建。未来人工确认默认进入持久队列；旧确认不会在升级后自动全库改写。

默认标签为：

| 人工结论 | 标签 |
|---|---|
| 有马赛克 | `有码` |
| 未见马赛克 | `无码` |

标签名称可自定义，必须非空且不同。这对标签互斥；修改结论时会更新本功能管理的状态，保留无关标签。算法疑似、低风险、失败及“未知”不写人工标签。

3.22.0 仅将精确旧默认组合 `像素化:有 / 像素化:未见` 升级为新默认；自定义或混合配置保留。升级不会自动重写历史外部标签。可按下一节选择旧确认补同步，已记录归属的旧标签按差量迁移；未确认归属的同名标签不会猜测删除。

- **NFO**：优先同名 `.nfo`；唯一归属的 `movie.nfo` / `tvshow.nfo` 可使用。多个视频共享 fallback，或同 stem 有多个视频扩展名时拒绝自动写入。支持时保留根级其他字段、类型、演员与注释，只变更根级受管标签。没有 NFO 可按设置创建最小同名 NFO；原有文件写入有并发校验和可恢复备份。
- **Jellyfin / Emby**：沿用全局服务器地址、API Key、媒体库范围和路径映射。只使用 API 精确路径匹配，匹配不唯一或服务器最新路径不一致时不写。写前重新读取条目，保留无关 Tags、Genres 和观看状态；不修改服务器数据库。

下方独立状态栏显示同步情况，按“NFO/服务器目标”分别计数。本地确认成功不等于两端都成功。未配置服务器显示等待，NFO 成功仍保留；失败只重试未完成目标，不回滚本地人工确认。

从“更多 → 标签同步 → 查看状态 / 重试”查看具体文件和每端错误。连接信息仍在全局设置；此处不额外保存一份连接配置。修改标签名或启用原来关闭的目标后，可以补同步，意图会按配置版本更新。

## 旧确认补同步和撤回

在“更多 → 历史与重新分析 → 加载全部历史”点击一次自动读完历史，调整筛选，进入“更多 → 标签同步 → 补同步当前筛选中的人工确认”，勾选要处理的项目。后台再次检查当前文件身份和有效人工记录；失效旧版本或算法低风险不会被当成可同步确认。

“此视频 → 撤回当前人工标记”会撤回本地有效确认，并为已同步目标排队恢复本功能的标签差量；保留同期新增的无关标签。成功撤回后结束本轮标签归属，下次确认重新记录基线。

首次服务器写入如果发生超时，可能无法知道服务器是否已应用。此时撤回不会猜测某个同名标签属于本功能而删除它，会显示“上次写入结果不明，需要核验”的未完成状态。核对并移除不应保留的残留后可重试完成。确认写入成功的差量则可以正常撤回。

文件替换后旧人工确认不再有效，旧队列不会给新文件套上旧结论。已写入外部 NFO / 服务器的标签代表此前确认，不能自动证明新文件内容；应对新版本重新检查、确认以更新标签。

## 检查、打包及验证范围

- 分流、取样、标签持久任务、配置/界面、撤回和异常行为均有合成数据回归；独立审查发现的四项重要边界已补失败回归并修复。
- 使用本机 `127.0.0.1` 合成 Jellyfin 服务器验证真实 HTTP 写入及撤回，两端无关标签和观看状态保留。测试不连接你的真实服务器，也不改真实媒体。
- 3.21.0 同时包含此前 3.20.1 通用修复。真实 FC2 内容、长片/NAS 吞吐和误检/漏检率未在本次标注评估，不能把合成测试当成实际内容准确率。
- 本地打包采用完整测试、静态检查、编译及版本检查后的精确源码摘要收据；未提交的本地源码会在构建清单中标明，默认正式发布仍要求干净源码。没有远端发布。

产物为 `dist/JellyfinToolkit/JellyfinToolkit.exe`（必须与同目录 `_internal` 一起使用）、`dist/JellyfinToolkit-v3.22.0-win64.zip` 及 `.sha256`。构建成功后的 `build-manifest.json` 记录实际版本、验证收据和 EXE 摘要；构建过程与测试日志在本地 `.local`。
