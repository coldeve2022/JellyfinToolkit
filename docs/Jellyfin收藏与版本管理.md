# Jellyfin 收藏与通用视频版本管理（3.22.0）

## 按喜欢和播放状态安排复核

在“像素化检查 → 更多 → Jellyfin 喜欢与播放状态”选择自己的账号，再同步。不会默认选择管理员或第一个用户；设置了多个账号时，喜欢和播放记录始终属于你明确选择的账号。全局媒体库范围、排除设置和路径映射继续生效。

可以使用本地 Jellyfin 数据库或服务器 API。未指定本地库时沿用现有自动发现；账号列表会显示同一数据库提供的用户名，缺少名称则显示用户 ID。服务器 API 需要全局设置中的地址和 API Key。本地库读取不需要 API Key，但必须能读取数据库且本地路径可访问。

“喜欢”“播放”和原有结论、工作流、文字搜索共同筛选；搜索还包括已同步的 Jellyfin 标题、标签和类型。“喜欢优先”将收藏排到前面，“普通排序”恢复之前的排序。新增的喜欢列默认靠近文件名，可通过工作区设置移动或隐藏。

- “只看喜欢且已确认有码”会启动完整历史加载，再按喜欢与人工结论筛选。历史较多时会逐批出现，可继续浏览或停止。
- “导入喜欢视频”把已同步且有唯一可访问本地路径的收藏加入原有检查流程，仍复用有效历史和缓存。
- 播放筛选包括未播放、播放中、已播放和未同步；无用户记录、无映射或条目不唯一时显示未知，不会当成未喜欢或未播放。

刷新在后台进行；失败或取消保留上一份完整快照，状态栏显示失败和上次数据。更换用户、服务器或范围后不会套用旧结果。服务器端新改的收藏需要再次同步；不会将本地缓存冒充实时服务器状态。

## 表格操作和默认标签

Ctrl+A 全选，Ctrl+C 复制可见选中项的文件名，Ctrl+Shift+C 复制完整路径，Ctrl+F 定位搜索框，Escape 清除选择。Alt+1 / Alt+2 进行人工确认，Alt+3 下一条；复核键可在工作区设置自定义。在文本输入框编辑时不会触发确认，多选确认仍会展示审核清单。

默认标签现在是“有码”和“无码”。只迁移精确旧默认组合，自定义名称保留。旧确认不会在启动时批量重写 NFO 和服务器；需要时从“更多 → 标签同步”选择历史人工确认补同步。

## 手动加入通用视频版本管理

选中当前筛选内的视频，点击“将选中视频加入版本管理”。这会把原文件清单传到通用管理页，不启动远程检索或替换。该页默认采用“通用版本升级”模式，以一张表显示新候选、原文件路径、完整标识和处理状态。

1. 左侧加入已经在本地的新视频，右侧确认原视频清单。
2. 生成预览，逐行检查配对。可接受文件名不同但完整标识一致；多个候选争用一个文件、标识歧义、相同文件或不同封装会阻止执行。
3. 保存继承快照。配置服务器时，需有效 API Key、精确路径匹配以及读取条目和用户状态的权限；配置不完整会阻止该行继续。
4. 审阅同一计划并确认执行。新内容替换到旧文件的原路径，不采用新文件的其他名称；因此保留同名 NFO、字幕、海报等附属文件和既有条目识别条件。原文件保留事务备份，可在任务中心查看和恢复。
5. 等服务器完成刷新，再执行继承核验。核对条目 ID、可编辑元数据和可访问用户的喜欢、播放状态、进度等；刷新请求被接收只表示排队，不代表继承完成。

准备、校验、备份和提交期间都会检查文件和服务器状态。若你或其他客户端修改了相关状态，会阻止提交，需重新预览。重启后可重新载入上次快照用于核验，不会直接执行旧计划。

## 当前限制和数据

本功能优先通过保留原路径维持同一 Jellyfin 条目，再用快照核验继承；不保证服务器重建条目、插件专有字段或无权限账号的所有信息都能自动恢复。差异或无法读取的用户会标为待处理，保留快照供人工恢复，不伪造播放会话、不在线改写服务器数据库。未配置服务器地址时可以只做本地文件管理，但没有服务器继承核验。

新文件不会自动成为“无码”确认；旧文件的检测确认会失效，新版应重新检查。已有外部标签是历史内容信息，需人工核对后更新。

扫描历史和人工结论继续使用原数据目录。喜欢快照位于数据目录的 `data/jellyfin_review.sqlite3`，版本继承快照和最新引用位于 `data/media_upgrades`，实际目录取决于启动时的数据目录。快照含媒体路径、元数据和用户记录，应随个人数据备份；发布压缩包不包含这些运行数据。

本轮回归使用隔离的文件、数据库和合成服务器；没有连接真实服务器执行替换。首次实际使用应先选少量文件核验映射、账号及备份，再扩大范围。
