# 媒体库范围与快速打标修复（3.11.0）

## 使用方法

1. 点击窗口顶部「选择媒体库 / 目录」。列表从当前数据源的 Jellyfin/Emby 媒体库配置读取，支持多个物理目录的媒体库。
2. 只处理电影时仅勾选「电影」。需要动漫画像时改选「动漫」并重新分析。首次没有选择时，库分析页面与固定操作栏均暂停开放。
3. 更细的目录可填写「额外目录」，每行一个**源服务器路径**，不要求本机存在。所选库和额外目录取并集；要只分析电影库的某个子目录，应取消媒体库勾选，仅填写该目录。
4. 可以明确选择分析全部库；该选择会合并其范围内的喜好，不能再假定电影与动漫分开训练。连接变化后需重新确认范围。
5. 快速打标支持全文搜索、内容分类、标签/类型勾选，多个标签可选全部满足（AND）或任一满足（OR）。标签选项可搜索，Tags 与 Genres 分开显示来源。筛选同时作用于卡片、可能喜欢、建议删除、已打标与 AI 建议；显示筛选后/总数。
6. 点击表头排序，拖动列边界调整宽度、拖动表头调整顺序。理由和标签列提供完整悬浮内容。常用操作保留在主区，AI 工具可展开。
7. 切换范围后重新分析。不同范围的新人工反馈、卡片进度、AI 特征和语义分数分别保存。此前全库人工保留/喜欢记录会用于保守删除保护，可在任务中心预览并明确采纳进当前范围；不会自动把旧 AI 缓存或负反馈当作当前范围的喜好证据。

## 根因与实现

原采集入口过滤了预告、主题等附属内容，但并未读取 CollectionFolder/VirtualFolders 的物理目录归属，所有主视频一起进入候选。状态上下文也只有来源和观看用户，没有分析范围。内容分类桶和番号只能描述内容特征，不能代替用户在 Jellyfin 里的媒体库分类。

- DB 读取支持实际 EF `BaseItems.Data.PhysicalLocationsList`、旧架构数据及服务器 `root/default/*/options.xml`；API 使用 VirtualFolders。媒体库 ID 与实际数据源绑定；已选 ID 不存在时明确失败，不退回全库。
- `library_source.collect` 先按原始服务器路径过滤，再进行本地路径映射；完整路径边界匹配，不把 `/movies-old` 当作 `/movies`。路径大小写按 Windows/POSIX 语义处理，不接收 `..` 跳转。
- 仅按额外目录筛选时不依赖 VirtualFolders 权限；每个额外目录也会形成归属信息。`score_snapshot` 在评分边界重新检查选择，避免绕过采集入口的宽范围快照直接进入画像。
- 状态上下文加入规范化库 ID/目录集合；共享快照键也包含范围。切换后清空统计、卡片、推荐、AI 报告与建议、删除/去重操作状态，旧任务结果不能重新绑定到新范围。当前有任务时不能切换。
- 操作身份从行号/文件路径中分离，快速打标以稳定 Item ID 定位；删除路径保存在独立角色中，数值排序不会覆盖路径。隐藏行不进入选中/全可见删除计划或 AI 采纳。
- 已知不同库的同番号不作为同一重复组比较；UI/AI 用稳定 group_id 关联建议。跨父目录同番号分集保守跳过，统计与界面明确说明，避免把无关内容合并。
- 仅切换范围时不重新搜索 Lada/Whisper 等无关第三方工具；未变化的其它窗口不重复处理全局配置广播。

## 验证与边界

2026-10-17 使用原始数据库的只读连接核验：发现动漫、电影、合集三个配置，电影有三个物理根目录，动漫有独立目录。本次主视频快照 6374 条：电影 5040 条（5039 个唯一路径），动漫 1334 条（1334 个唯一路径），电影与动漫 ID 集合交叉为 0。合集为虚拟分类，本次物理目录筛选为 0。上述数量属于核验快照，会随服务器内容变化。

新增回归覆盖库发现和实际 EF 元数据形态、DB/API 范围匹配、路径映射、取消、失效 ID、无目录权限时手动路径、来源切换、状态隔离、旧反馈保护及迁移、不同库同番号、表格筛选排序后的正确操作对象、隐藏行保护、卡片打标撤销、数值排序及固定操作栏入口。完整发布门禁和构建验收的最终结果随交付报告提供。

媒体库采集始终只读；本次验证没有修改真实用户配置、Jellyfin 库、播放记录或媒体。选择分析范围本身不会移动视频或改写服务器分类。手工添加文件的处理页面继续按其明确输入工作，不受库元数据筛选代替；从库挑选的入口使用统一范围。

库目录筛选基于物理路径：虚拟合集不是物理媒体目录，不能等价于合集成员查询。缺失元数据不会被猜成某类，也不会按「没有番号」自动排除。单个库内仍可能包含多种内容；需要更细隔离时可建立更多 Jellyfin 库或选择更细的源目录。
