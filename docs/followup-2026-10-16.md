# 3.10.1 反馈修复与验收范围

本轮基于用户实际使用反馈修复三类问题：文件输入不可达、媒体库附属内容计数、本地 AI 连接与模型检测。基线保留既有 CI 和 Qt 收尾修正，开始提交为 `ac47b16`。

上一轮验收遗漏了操作系统拖拽事件到实际队列的入口链路，也没有用实际数据库的附属条目分布校验概览口径。本轮补充真实 Qt viewport 事件、文件/目录选择到预览的行为回归，并以只读聚合结果核验库统计。

## 验收要求

- 文件处理页都有可发现的添加入口；文件与目录经过相同过滤进入可见队列，拖拽通过真实 viewport 事件验证。运行中拒绝输入，不绕开审核计划。
- DB/API/旧库统一排除有明确附属证据的条目，保留正片与无法确定的泛视频。概览区分条目、文件与作品分组；画像不重复计算同一文件的行为证据。
- 模型发现支持配置的 OpenAI 兼容接口，准确处理本机 Ollama、鉴权和错误。只对明确本机 Ollama 提供启动重试，不猜测其它服务，不下载模型。
- 完整测试、真实只读库数量核验、Qt 操作链、实际本机 AI 连接及独立 Windows 包烟测留存证据。

## 已实施的公共入口

- `ui.widgets` 的 URL 拖放支持真实 view/viewport 接收，仅复制、延迟投递，并服从页面任务锁；`FileInputActions` 为缺少入口的页面提供文件/目录选择。NFO 页一次明确处理一个目录，不再静默只取多个目录中的首个。
- `utils.media_filter` 在 EF/旧库/API 采集处筛选主视频，携带只含汇总数字的 `collection_stats`；`summarize` 提供条目、规范路径和作品分组计数。无法确定的远程文件不假定已删除，明确的主片类型不因普通词误伤。
- 画像按同路径合并行为证据，原始 alias ID 和人工反馈继续用于执行前保护；统计的唯一路径数不是磁盘全量文件盘点，也不声称逐个核对硬链接。
- 封面只查询本次主视频 ID，缓存重复封面路径检查并支持取消。概览复用纯元数据重复候选分组，不为计数启动 FFprobe，也不据此做删除决定；重复处理实际执行前的质量保护保留。
- `utils.local_ai` 为模型发现和推理提供共同端点/代理/鉴权处理；设置页读取当前编辑内容，区分拒绝、超时和鉴权错误。只有明确的已安装本机 Ollama 可以通过按钮后台启动重试。

## 新回归与交付门禁

`test_input_workflows_followup.py` 通过 Qt viewport 发送拖放事件，覆盖文件/目录选择到队列、预览及输入锁；`test_library_count_followup.py` 覆盖 EF/API/旧库、附属元数据、主片反例、同路径反馈、封面范围和概览无探测；`test_local_ai_followup.py` 覆盖两套协议、自定义前缀、代理、鉴权、安全错误、取消和启动重复请求；`test_count_explanation_followup.py` 验证可见计数口径和安装依赖一致性。

逐项修复先记录失败回归，再实现并验证。完整测试、构建资源和 EXE 烟测结果保存在独立交付报告，以绑定最终提交和源码摘要的发布验证记录为准。实际库只读聚合和本机服务检测证据保留在本地，不进入公开源码。
