# 3.25.0：标记按钮、批量补图与深检

## 使用方式

- 表格Ctrl/Shift多选后，点“补抓选中证据图”：每个视频最多补24张新的参考画面，保留原检测和人工结论。可在任务进行中继续选择其他项并提交，按原并发设置有界处理。
- “更多”或表格右键→“补抓当前筛选中缺图的视频”：仅在当前可见范围后台检查无路径/图片文件缺失/零字节项，忽略已有可用证据的项，不扩到整库。
- “深入检查选中项”：明确重新分析、通常三倍计划帧数（上限600），保留更多概览与结构候选。证据预算为min(60,max(24,原证据数量×2))，默认18时最多36张；不保证所有视频有足够独立画面填满预算。
- 每轮补图/深检调整分层取样相位，后续实际取样时刻变化；重复画面仍去重。补图总保留上限60，优先保留旧结构证据及本轮新图。完全静态、极短或解码失败的视频可能没有新增图片，界面显示实际新增和重复数量。
- 补图不重新判定像素化，不把已有失败分析改成完成；分析失败与新参考图可同时存在。人工确认以当前文件版本的权威标签为准，不清空、撤回或重做原人工确认。
- 页面停止、任务中心全部停止、关闭均取消未开始请求。队列是当前会话内请求，不在下次启动自动执行；已保存的图片和回执留在资料库。

## 根因和改动边界

| 问题 | 根因 | 修复 |
|---|---|---|
| 标记后按钮短暂变灰 | 标签同步由页面拥有的任务执行，通用锁把标记按钮也禁用 | 同步worker显式taskPreserveReview；标记控件taskReviewInteractive。其他任务锁定逻辑保留。 |
| 多选也只深检一条 | _deepen_current只读取_current | 共同选中可见路径入口，多选一次提交，右键已有选择不清空。 |
| 分析180帧仍只有六张概览 | 检测器和服务两层限制普通候选数量；概览只补到六张 | 显式evidence_frames预算、保留全时段概览；结构阈值/独立强证据门槛不变。 |
| 再次深检画面近似不变 | 固定分层抖动每次取同一时刻 | 持久轮次与相位，普通检查默认相位0不变；合成视频核对实际PTS变化。 |
| 后段超时导致先前画面全部丢失 | 异常跳过候选整理与写图 | 对取样失败保存已解码画面，再传播原错误；取消仍及时停止。 |
| 补图把“上次检查失败”变成成功 | 补图若只拿旧成功缓存当返回基线，吞掉当前UI失败 | 当前同版本UI基线与持久成功缓存分别补图，保留各自分析状态；权威人工标签共同事务融合。 |
| 重复图没有新增时，下次还是同轮次 | 仅有fresh图片才写回，丢失操作回执 | 同版本基线的非取消回执持久化；零新增也推进轮次并显示重复数。 |
| 停止全部时队列间隙仍会启动 | 只有定时器排队，TaskManager不知道待启动拥有者 | track_pending_owner纳入统一停止代次；队列定时器检查epoch并清理。 |

新增censor/evidence_refresh.py封装参考补图、有效旧图、轮次和独立回执。CensorScanWorker复用发现、有界线程池、进度、取消与GUI结果交付；参考补图模式不enqueue/完成普通分析待办。普通CensorOptions默认新字段从签名排除，保留3.24.1普通自动缓存兼容；数据库schema、固定资料库登记不变。

## 验证与限制

测试使用隔离资料库和普通合成文件，不读取用户真实视频、NFO、服务器或人工记录。test_review_evidence_refresh.py覆盖按钮合作锁、真实同步pump、多选/右键、队列范围与停止、失败/文件变更/并发人工确认、旧缓存与新UI状态、后段失败保图、合成FFmpeg多轮取样及图片可解码。

首轮实际失败回归见.local/evidence-red.log，补充失败回归见evidence-extra-red、evidence-projection-red、evidence-queue-red。测试装置曾误用worker.stats计数及未关闭原生右键菜单，按已有task_status协议和真实Qt定时关闭修正，未提高用例超时或删除断言。完整验收以.local/evidence-release-final.log、build/verification.json和包内build-manifest为准。

首轮全量1829通过、1失败、1平台跳过（365.92秒，.local/evidence-release-attempt1.log），在工作区偏好测试中捕获到Qt对象清理后访问已不存在owner的异常。补充test_workspace_event_lifetime.py的Hide/Close两个确定性失败回归，加入清理期保护；正常拥有者保存行为仍验证。最终全量另行完整重跑。新增专项21项及生命周期2项，不通过跳过原用例掩盖失败。

未验证用户这几部具体视频的解码可用性，损坏/加密/路径不可访问/超时仍可能抓不到图。静态片段不会凭空生成新内容。补图保留检测结论，不能用新增参考图数量当准确率；本轮不声称检测速度整体提升，也未修改专用检索生产代码。

新版本独立输出dist/v3.25.0，旧程序及真实资料库保留。当前源码未提交，交接须携带新增模块/测试/文档，不能只复制原Git HEAD。
