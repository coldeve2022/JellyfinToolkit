# 像素化：两个阶段、状态与工作流

> 本文保留领域状态的设计背景。v3.20 完整操作路径与配置请看 [检测与版本替换使用指南](检测与版本替换使用指南.md)。

> 代码：`censor/review_route.py`（唯一判定入口）、`ui/pages/censorship.py`
> 版本：v3.18.0 起

---

## 1. 这是一件事还是两件事

**两件。** 而且必须分开算。

| | 阶段一 · 定标记 | 阶段二 · 找替换 |
| --- | --- | --- |
| 问题 | 这部片**到底有没有码** | 网上有没有**无码版**可以换 |
| 靠什么 | 看画面 + 你的判断 | 按番号查 JavDB / JavBus / Supjav |
| 产出 | 一条**标记**：有码 / 无码 | 一份候选清单（确有 / 疑似 / 未见 / 未查） |
| 谁说了算 | 你 | 站点 |
| 失败代价 | 标错了，后面全歪 | 查不到，但这不影响"有没有码"的结论 |

**关键约束：阶段二只吃阶段一的产出。**

只有你亲手标记为「有码」的片子，才会进入找替换的队列。
算法判的"疑似有码"不查 —— 那只是猜测，拿猜测去查等于用假设喂流程：
查了可能根本没有对标的无码版，还会让你误以为"这部片有得换"。

> 上一版正是错在这里：扫描一结束就把所有 `state=CENSORED` 的片送去检索。
> 那是把两个阶段揉成了一条流水线，历史统计也混在一起，
> 于是"还有多少要我看"和"还有多少要去网上查"分不清。

## 2. 阶段一：两个维度

### 结论（这个文件到底有没有码）

| 值 | 含义 | 谁能给出 |
| --- | --- | --- |
| **有码** | 画面里检出了马赛克网格 | 画面检测（≥0.60）**或**你标记 |
| **无码** | 画面里没有码 | **只有你标记** |
| **未定** | 证据不足 | 其余情况 |

> 自动流程永远给不出「无码」。抽 60 帧没找到网格只说明"这次没找到"，
> 不构成"整片没有"的证明。最接近的自动结果叫 **低风险** —— 它是处理状态，不是结论。

### 处理（这个结果还需不需要我）

| 值 | 含义 | 算待办吗 |
| --- | --- | --- |
| **排队中** | 已导入、还没检查 | ✅ |
| **未完成** | 失败 / 取消 / 部分完成 | ✅ |
| **待复核** | 检查完了，但证据不足以下结论 | ✅ |
| **已确认** | 你打过标记（有码或无码） | ❌ |
| **低风险** | 抽样覆盖足够、未检出网格 | ❌ |
| **已延后** | 文件名有明确无码/破解线索，按名称延后 | ❌ |

「待我处理」= 排队中 + 未完成 + 待复核。

**阶段一的唯一任务：把「有码」定下来。** 界面上的红色按钮就是「标记『有码』」，
标记完这条片会自动进入阶段二队列。

## 3. 一个视频的一生

```
导入 ─→ 排队中 ─→ 检查中 ─→ ├─ 有码（画面证据）─┐
                            ├─ 未定 ────────────┼─→ 待复核 ─→ 你标记 ─→ 已确认
                            │                   │              ├ 有码 → 进阶段二
                            │                   │              └ 无码 → 结束
                            ├─ 低风险（自动）───→ 暂不处理
                            └─ 已延后（名称线索）→ 暂不处理
                    └─ 未完成（失败/取消）──→ 重试

已确认有码 ─→ 按番号查站点 ─→ 确有 / 疑似 / 未见 / 未查 ─→ 下载替换
```

## 4. 界面：5 个视图，前 4 个属于阶段一

| 视图 | 装什么 |
| --- | --- |
| **待我处理 (37)** | 排队中 + 未完成 + 待复核 |
| **全部记录 (205)** | 所有检查记录 |
| **已确认 (19)** | 你标记过的（有码 + 无码） |
| **暂不处理 (44)** | 低风险 + 已延后 |

阶段二有自己的页面 —— 左侧导航 **「🔎 找无码版」**（`ui/pages/censor_replace.py`）。
这一页不显示检索结果，只负责定标记；检索结果全在那一页，互不干扰。

结论下拉：全部 / 有码 / 无码 / 未定。两个维度独立 AND。

表格列：`文件名 | 结论 | 处理 | 记录来源`（标识/结构分/依据默认收起）。

**所有列都能手动拖宽**，最后一列自动占满剩余；表头还能拖动换位。

状态栏只报检查进度，并指向另一页：

```
列表 205 · 待处理 37 · 已确认有码 12（在「找无码版」页检索） · 已确认无码 7 · 低风险 40 · 已延后 9
```

## 4.1 阶段二页面：「🔎 找无码版」

**按番号聚合**（同一部片的多个副本只占一行），列：`番号 | 片数 | 检索结果 | 候选 | 最大种子 | 最近检索`。

| 操作 | 做什么 |
| --- | --- |
| 刷新清单 | 重读库里「已确认有码」的记录（不联网） |
| 检索未查 | 只查还没结果 / 结果过期的番号 |
| 全部重查 | 忽略缓存，全部重查 |
| 导出清单 | CSV：番号、检索结果、最大种子、磁链、文件路径 |

右栏是候选条目（打开页面 / 复制磁链）与该番号包含的文件。
标记「有码」时本页清单会立刻入队一条（**只入队，不联网**），
所以关掉程序也不会漏；要不要真去查、什么时候查，由你在这页决定。

## 5. 不遗漏、不重复

### 5.1 打开页面自动接过待办

`showEvent` 第一次触发时读 `store.review_queue(limit=300)`，铺进列表并切到「① 待我处理」。
以前要手动点「更多 → 加载历史记录」，关一次程序待办就等于丢了。

### 5.2 重复导入不重算

导入时先问 `CensorService.cached_result(path, options)`：命中有效缓存的不进扫描队列，
直接铺回列表标「复用分析」。判据是文件身份 + 分析签名，所以换过文件、改过配置、
NFO 变过照样重算。整批都命中时状态栏写 `N 个视频沿用上次结果，本次无需重查`。

### 5.3 检索去重与触发

- 触发点只有两个：**你点「标记『有码』」**，以及切到「② 找替换」后点「检索无码版」；
- 按番号去重：同一部片的多份副本共享一条检索结果；
- 已查过（含没命中）不会重复发起；失败 3 次熔断，避免拖垮整批。

## 6. 常见疑问

**为什么不能扫完就自动查无码版？**
因为那时"有码"还是算法猜的。查的是"有没有对标的无码版"，前提是"这部片确实有码"。
前提没被确认，查了也没法用。所以顺序必须是：**先定标记，再找替换。**

**为什么「无码」只能人工确认？**
程序能证明"这里有码"（找到了网格），证明不了"这里没有"（抽样之外可能还有）。

**「低风险」是不是等于没问题？**
不等于。它是"抽样 ≥24 帧、覆盖目标 80%、≥4 种画面，且最高分低于候选阈值"。
覆盖够但仍是抽样，所以不进待办，也不改结论。

**为什么两个阶段的历史要分开算？**
因为它们是两种完全不同的工作：一个是"看片子定性质"，一个是"上网找资源"。
混在一个数字里，你既看不出还剩多少要审，也看不出还剩多少要查。
